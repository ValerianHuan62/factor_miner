# Factor Miner 项目面试讲解

这份文档用于在面试前快速复习。它解释项目做了什么、为什么这样设计，以及怎样准确介绍当前成果。

## 60 秒介绍

“Factor Miner 是我做的量化因子研究系统。它解决的问题是，传统因子研究里论文阅读、公式实现、回测、去重和结果记录往往是分散的，容易出现事后解释、未来信息或重复试验不留痕的问题。

我把流程固定成一条链：先把论文和经济学直觉写成可证伪的假设，再冻结数据和评价条件；然后用受限 DSL 生成可审计公式，在真实面板上计算原始因子，分别做 IC 统计检验和带交易成本的因果回测，最后做公式查重、输出相关性和联合贡献分析。结果写入不可变账本，Dashboard 只读取这些结果。

目前我已经对 A 股 51 个既有候选做了联合冗余诊断，审核采纳了 36 个研究代表，供后续策略和模型训练使用。这里的‘采纳’是研究库选择，不等于这些因子已经被证明是实盘 Alpha；独立统计确认和经济机制验证仍然单独记录。”

| 主题 | 可以怎么讲 | 代码或界面位置 |
| --- | --- | --- |
| 研究问题 | 因子不是公式竞赛，而是要证明经济逻辑、可测量性、预测信息、可交易性和独立增量。 | `README.md`、`docs/当前流程与日常使用.md` |
| 研究约束 | 在查看结果前冻结假设、数据、样本、成本与统计族；失败与重复仍保留。 | `src/factor_miner/favor_workflow.py`、`ledger.py` |
| 防止泄漏 | 公式只能使用白名单 AST；禁止未来函数、标签泄漏和任意 Python；数据按可得日对齐。 | `dsl.py`、`compiler.py`、`dsl_semantics.py` |
| 评估与回测 | 用 IC/RankIC 与 HAC、多重检验看预测信息；用信号日排序、后续成交和成本看交易表现。 | `evaluation.py`、`causal_backtest.py` |

## 常见追问

### 为什么需要 LLM？会不会变成黑箱挖因子？

LLM 只负责受控的研究辅助，例如把已冻结的经济假设表达为候选公式。它不能改数据、样本、成本、统计标准或试验预算。公式最终必须经过同一套类型检查、确定性编译和真实数据验证；人工公式也走同一条链。因此 LLM 的角色是提高假设到表达式的效率，不是替代研究判断。

### 怎么防止未来信息和回测偏差？

第一层是公式层：AST 白名单拒绝未来函数、负 shift、居中滚动和任意执行代码。第二层是数据层：基本面按可得日对齐，市场必须显式提供计算、排名和交易 mask。第三层是研究层：先冻结标签、切分和成本，再评价；排序只使用信号日信息，无法成交的头寸不假装成交。

### 为什么不只看 Sharpe 或回测收益？

一个回测指标可能来自特定样本、交易假设或偶然暴露。系统把预测信息、统计显著性、交易收益、成本敏感性和风险诊断分开保存。IC 显著性使用时间依赖稳健的 HAC，并在多候选场景使用 Bonferroni 校正；回测则单独处理成交和终值问题。

### 怎么判断两个因子重复？

只看相关性不够，因为同一公式的不同写法、或不同机制但相近的样本表现，都可能混在一起。系统先比较规范 AST 和哈希，再在共同日期和共同股票池上计算逐日截面 Spearman 相关性。对既有候选集合还会做删除实验、重训子集或组 Shapley，帮助选择一个研究代表并保留同类替补。

### 36 个 A 股因子是什么状态？

它们是从 51 个既有候选的联合冗余诊断中审核采纳的研究代表，用于下一阶段策略和模型研究。这个状态不替代单因子的独立统计确认；若缺少独立机制检验，仍是 `mechanism_unverified`。介绍时不要称为“已经验证的实盘 Alpha”。

### A 股和美股是否共用一套系统？

共用的是研究流程、候选合同、公式编译、统计原则、回测边界和账本；不同的是数据发布、交易日历、状态 mask、成本和市场分区。系统要求每个市场显式提供可计算、可排名和可交易的状态，而不是自行猜测停牌、涨跌停或退市含义。

### Dashboard 和 API 起什么作用？

Dashboard 负责把账本里的候选、指标、回测和审核状态展示成可查阅的研究界面。API 入口要求用户先配置本机密钥、导入完整计划并手动启动；它调用同一条正式 CLI 验证链，不会在网页里另建一套更宽松的标准。API 发送的是授权的公开研究假设与测量合同，不发送私有行情和完整结果。

## 推荐演示顺序

1. 先打开 Dashboard 的“看结果”，说明指标、审核状态和原始统计确认是两套字段。
2. 打开“研究代表库”，说明代表与同类替补的区别，以及为什么做冗余诊断。
3. 打开一个因子的详情，按“假设 → 公式 → IC → 回测 → 冗余”讲完整链条。
4. 展示“API 研究”页面的冻结计划和预检信息，说明按钮只是调度正式 CLI，不跳过研究合同。
5. 最后展示原始特征宽表的交付合同，说明它会进入下游 Dataset 与模型训练，但本身不混入标签或预处理。

## 术语速查

| 术语 | 含义 |
| --- | --- |
| 候选因子 | 已登记、可计算和可评价的研究对象，不代表已通过所有验证。 |
| 原始因子 | 公式直接计算出的数值，不含标准化、排名或标签。 |
| IC / RankIC | 因子与未来标签之间的相关性及其秩相关，用于衡量预测信息。 |
| HAC | 对时间相关和异方差更稳健的显著性估计方式。 |
| 冗余 | 因子在公式结构或样本输出上重复，未必能提供额外信息。 |
| 研究代表 | 联合诊断后被审核为默认研究输入的成员，不会改写其原统计资格。 |
| `mechanism_unverified` | 尚未完成独立经济机制检验，不能把统计结果当成机制证明。 |

## 讲解时应坚持的边界

- 不把历史筛选过的区间描述为全新的样本外结果。
- 不把审核采纳、统计通过、机制验证和实盘可用混成一个结论。
- 不把 PostgreSQL 或 Dashboard 说成事实源；可追溯的 JSON/JSONL 与运行产物才是事实源。
- 不展示私有行情、真实候选详情、完整研究产物或 API Key；公开仓库只保留代码、测试、示例和文档。
