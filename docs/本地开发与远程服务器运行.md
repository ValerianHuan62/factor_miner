# 本地开发与远程服务器运行

## 推荐结构

```text
GitHub 公开代码仓库
  ├── 新电脑：代码编辑、合成测试、提交与远程控制
  └── Linux 研究服务器：只读 QuantLake、真实计算、Worker、PostgreSQL、Dashboard
```

GitHub 只保存代码、测试和无密钥模板。真实行情、运行产物、数据库和 Token 留在研究服务器，不随 `git clone` 移动。

## 新电脑连接现有服务器

在新电脑的 `~/.ssh/config` 中配置别名，地址和用户名由你现场填写：

```sshconfig
Host quant-research
    HostName <server-ip-or-domain>
    User <server-user>
    IdentityFile ~/.ssh/id_ed25519
    ServerAliveInterval 30
```

验证连接：

```bash
ssh quant-research
```

建议使用 SSH Key，不把服务器密码写进仓库、脚本或 shell history。

## 本地开发、服务器执行

```bash
# 新电脑
git clone https://github.com/ValerianHuan62/factor_miner.git
cd factor_miner
uv sync --frozen --extra dashboard
uv run python -m unittest discover -s tests

# 登录服务器，在服务器 clone 同一仓库
ssh quant-research
git clone https://github.com/ValerianHuan62/factor_miner.git /opt/factor-miner
cd /opt/factor-miner
uv sync --frozen --extra dashboard
```

后续同步代码：

```bash
# 新电脑提交并推送
git push origin main

# 服务器只拉取已审核提交
ssh quant-research 'git -C /opt/factor-miner pull --ff-only origin main'
```

不要在服务器有未提交修改时直接 `pull`。先运行 `git status --short`，确保不会覆盖现场配置或代码。

## 接回现有 QuantLake

真实模式仍使用服务器上的只读 `/data/quantlake`。服务器私有配置从模板复制，不提交 Git：

```bash
cd /opt/factor-miner
cp configs/company_a_share.env.example /var/lib/factor-miner/private/factor-miner.env
chmod 600 /var/lib/factor-miner/private/factor-miner.env
```

至少需要现场填写以下类别：

- QuantLake release、manifest、SHA-256 和 cutoff
- market/state/label URI
- 独立 artifact root
- 参考因子 manifest
- `DEEPSEEK_API_KEY`
- PostgreSQL DSN
- 代码 commit 与配置 hash

这些字段不能只填占位符；真实模式会在读取数据前核验它们。

## 启动 Worker 与 Dashboard

`deploy/` 中的 systemd 模板默认使用：

```text
代码：/opt/factor-miner
私有配置：/var/lib/factor-miner/private
研究配置：/var/lib/factor-miner/config
```

若服务器使用其他目录，安装前修改模板即可。现有服务器服务不会因为 GitHub 仓库中的模板变化而自动改变。

Dashboard 默认只监听服务器 `127.0.0.1:8501`。从新电脑建立安全隧道：

```bash
ssh -L 18501:127.0.0.1:8501 quant-research
```

然后打开 `http://127.0.0.1:18501`。

## Mac 能运行到哪一步

- 可以：安装全部依赖、运行 CLI、编译因子 DSL、运行 707 项合成测试、编辑配置、通过 SSH 控制服务器。
- 默认不可以：在 macOS 原生环境形成真实 A 股研究结论。真实入口要求授权 Linux、只读 `/data/quantlake` 和完整数据身份。
- 可以迁移：换到新的 Linux 工作站或服务器后，只需 clone 仓库、恢复私有配置并挂载满足合同的数据发布；不依赖当前 Mac 的个人目录。
