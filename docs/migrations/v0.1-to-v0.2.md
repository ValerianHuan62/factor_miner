# 从 V0.1 迁移到 V0.2

## 迁移原则

V0.2 不覆盖 V0.1 的政策、研究族、批次、候选身份或历史产物。它为同一个原始候选建立新的参考库、评价政策、研究族和批次，再执行增量信息评价。

已经打开过 V0.1 可见结果的试验名额不能伪装成新的 V0.2 预登记试验。

## 新增状态对象

V0.2 增加：

```text
state/reference_libraries/<reflib_id>.json
```

参考库冻结清单 ID、清单 SHA-256、有序因子 ID 和来源。任何变化都会生成新的 `reflib_id`。

## 登记顺序

服务器真实运行按以下顺序准备：

1. 生成并核验参考因子 Parquet 与参考清单；
2. 用真实清单 SHA-256 生成 `ReferenceFactorLibrarySpec`；
3. 执行 `register-reference-library`；
4. 用返回的 `reflib_id` 生成代码内置 V0.2 政策并执行 `register-policy`；
5. 为 V0.2 建立新的研究族；
6. 登记候选和新的 V0.2 campaign；
7. 先执行两次 `run-smoke`，再执行 `run-visible`；
8. 执行 `ledger-verify` 并核对运行清单和候选包。

仓库示例中的 `aaaaaaaa...` 是结构占位值，禁止用于真实登记。

## CLI 变化

新增命令：

```bash
factor-miner register-reference-library \
  reference-library.json \
  --artifact-root "$FM_ARTIFACT_ROOT"
```

`register-policy` 根据 `policy_version` 读取 V0.1 或 V0.2 schema。V0.2 政策必须引用已登记参考库，并且必须等于代码构造的公司 A 股冻结政策。

`run-visible` 根据已登记政策版本自动选择 V0.1 或 V0.2 工作流，没有绕过增量闸门的参数。

## 环境配置

原有参考清单变量继续使用：

```text
FM_REFERENCE_MANIFEST_PATH
FM_REFERENCE_MANIFEST_SHA256
```

V0.2 额外要求环境中的清单 SHA-256 与已登记参考库完全一致。文件存在但哈希不同会在打开结果标签前失败。

## 兼容性

- V0.1 的政策 ID 保持 `evalpol_cd9a83fb7dcaece5139e5353`；
- V0.1 CLI 和产物语义不变；
- V0.2 候选仍使用原有可信候选 schema，因为原始公式没有变化；
- V0.2 新增 `incremental_information.json` 和 `incremental_failed` 终态；
- V0.2 产物不得叫作 Evidence、Conclusion、认证因子或生产 Alpha。

## 回退

回退代码不会删除或改写 V0.2 账本。旧版本仍可读取和重放 V0.1 对象；V0.2 状态和产物保留供审计。若需纠错，只能追加带替代关系的新事件，不能修改已有 JSONL 行。
