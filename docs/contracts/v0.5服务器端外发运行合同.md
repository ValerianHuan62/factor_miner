# V0.5 服务器端外发运行合同

## 目的

DeepSeek 的真实调用只能在公司 Linux 服务器完成。Codex 或 Mac 不读取 `/data/quantlake`，不拼接原始覆盖图谱，也不接触 API 密钥；它们只能提交运行命令并接收不含研究正文的运行摘要。

## 请求包

服务器固定编排器必须先在以下目录生成三个不可变文件：

```text
/data/factor_miner_artifacts/state/llm_server_runs/{family_id}/
├── approved_request.json
├── corporate_policy.json
└── export_authorization.json
```

`approved_request.json` 必须是 `PreparedDeepSeekRequest`，其中的 `request_sha256` 与待发送规范 JSON 字节一致。`corporate_policy.json` 必须是公司批准的 `CorporateExternalResearchPolicy`；`export_authorization.json` 必须绑定同一请求哈希、政策身份、批准角色和有效期。

请求包有两种模式：

- `public_capability_only`：只允许公共经济学问题、公开字段别名、白名单算子、窗口能力和 AST Schema，不读取覆盖图谱。
- `sanitized_coverage_brief`：必须通过 `LLMCoverageBrief` 脱敏 Schema、公司政策和精确请求哈希授权；不得包含真实因子 ID、个股、公式、IC 序列、收益矩阵或 Barra 结果。

个人 V1 试运行在 `expression` 与 `semantic_lint` 批次中可以使用
`LLMCampaignScopeAuthorization`。它是绑定一个研究族的轻量范围授权，不要求操作者
逐个复制请求哈希；每次请求仍必须通过固定程序的 payload 扫描、角色、信息类别、调用
次数、模型、端点和有效期检查。范围授权只能覆盖 `public_capability_only` 等已获政策
允许的脱敏类别，不能把原始行情、个股、IC、收益、Sharpe 或 Barra 结果升级为可外发。
高风险或单次试验继续使用上面的精确请求哈希授权。

## 运行命令

在服务器上执行：

```bash
factor-miner llm server-run-approved \
  --artifact-root /data/factor_miner_artifacts \
  --mode sanitized_coverage_brief \
  llmfamily_<approved-family-id>
```

运行器只访问固定请求包、固定 DeepSeek 官方 endpoint 和服务器环境变量 `DEEPSEEK_API_KEY`。请求、响应和调用清单保存在服务器运行产物目录，标准输出只返回：

- `run_id`；
- 请求哈希；
- 完成/失败状态；
- 终结槽位数；
- 产物清单哈希；
- 稳定失败码（如有）。

标准输出禁止出现 prompt、响应正文、个股代码、行情值、完整 IC、完整 Barra 暴露、API 密钥和数据库连接串。

## 失败语义

运行前的模式、政策、授权和 Schema 错误直接硬失败。供应商不可用或响应格式无效时，已经产生的请求哈希和调用录制仍保留，运行摘要进入 `failed` 终态；不能自动补抽新槽位。重复执行同一运行摘要只返回原摘要，不重复调用 DeepSeek。

## 边界

服务器在内网不改变外部模型政策。若公司不允许 `sanitized_coverage_brief` 外发，该模式必须硬失败；此时只能使用 `public_capability_only`，或改用公司边界内模型。通过该合同的 DeepSeek 仍不能看到回测结果，也不能修改评价政策或候选槽位预算。
