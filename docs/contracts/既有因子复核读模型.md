# 既有因子复核读模型

既有因子复核区分研究输入资格、经济表现与新颖性。已知机制不自动淘汰；统计通过也不自动证明可交易收益或经济机制。

## 评价边界

复核前将方向、双区间门槛、多重检验家族、构念要求、相关阈值与代表排序写入独立协议文件。读取既有因子报告时沿用原方向和校正结果，不反向，不删除失败槽位。确认区间已被观察的复核明确记录为事后诊断，不宣称密封样本外。

分类为保留基底、同类替补、观察池和未保留。统计失败不进入基底；统计符合但构念证据不足的候选进入观察池。合格候选按发现期强度去重，不按确认收益选窗口。单因子成本压力用于揭示经济风险，不代替模型输入的统计评价。

## 读模型合同

市场配置可显式指定 `library_review_path`。文件版本为 `library-review-v1`，包含 `market_id`、`by_factor` 与中文摘要 `message`。每个因子条目必须有 `source_candidate_id`、原报告内容的 `report_sha256`、`status`、`label` 和 `reasons`。

Dashboard 在原报告之上叠加复核标签；不修改原始报告、假设、账本或统计结论。市场不一致、引用编号缺失、候选身份不符或原报告内容变化时拒绝使用复核清单。跨市场相似公式必须明确标注来源市场及编号，只影响新颖性。

复核后的首页默认显示“在研因子”，包含保留基底、观察池和同类替补。“淘汰档案”展示本轮未保留候选，仍可查阅原始指标及失败理由；“因子”和“全部”继续包含历史未保留记录。归档只是展示分区，不代表候选永久无效，也不代表观察池与替补通过了全部闸门。IC、RankIC以原始数值排序，显示四位小数；卡片字号随容器宽度变化。实际收益缺失时仍不允许用最后报价或零回收情景填充实际指标。

## PostgreSQL 筛选留库与精简记录

### 组合研究资格的独立版本

`research_pool_path` 可配置 `research-pool-dashboard-v1` 组合研究读模型。首页提供“组合研究池”和“恢复研究”，同时保留原单因子处理状态；原统计失败者即使恢复研究资格，也不得变更原 `statistical_pass`。原报告候选身份与内容摘要必须一致。具体资格见[组合研究池与有限机制预算](组合研究池与有限机制预算.md)。

PostgreSQL 的 `public.factor_research_pool` 按市场、复核版本和稳定编号保存研究代表，区分原状态、原统计结果和新研究资格。该表不改写 `screened_factors` 或 `factor_trial_records`；后两表继续表达原统计留库及完整试验历史。新增研究代表不是已验证盈利策略，联合贡献与成本结果必须单列。

```bash
python -m dashboard.research_pool_store --pool <研究池读模型> --receipt-root <新发布回执目录>
```

美股日常查询统一使用 `public.screened_factors`，只收录复核状态为 `retained`、`reserve`、`watch` 且统计通过的候选。状态继续区分基底、同类替补和观察，不能把“留库”解释为全部研究闸门通过。该表提供完整 IC 数值、明确为空的未知实际收益、独立参考估值、当前报告和筛选理由；旧 `factors` 与 `factor_metrics` 不再是美股完整名录。数据库指标读取入口优先使用新表，其他市场不受影响。

`public.factor_trial_records` 每个候选身份只留一条精简索引，覆盖留库、淘汰、编译失败以及已登记未筛选的尝试。记录状态、原因、原检验族、摘要统计、稳定业务编号和原始文件位置；不复制逐日曲线、持仓、完整假设或大矩阵。未分配业务编号的编译失败仍以候选身份留痕。此表是可重建投影，正式试验事件仍以文件账本为准。

迁移先核对筛选报告内容及稳定编号，保存受影响旧行和计划，在单一事务内更新两表并移除已核验淘汰编号的旧详细投影。不得删除 `factor_id_map`，不能因清理而缩小试验族。未识别历史不能自动删除；数量或身份不符必须失败。新批次登记及完成筛选后自动同步，数据库失败时保留文件产物并通过独立投影命令补齐，不能重新执行已完成研究。

```sql
-- 默认只看筛选留库的因子。
SELECT factor_id, factor_name, screening_status, ic_mean, rank_ic_mean,
       annualized_return, reference_annualized_return, unresolved_position_count
FROM public.screened_factors
ORDER BY factor_id;

-- 试验数量按状态统计；不拿留库数量充当试验总数。
SELECT status, count(*) FROM public.factor_trial_records GROUP BY status;
```

发布入口为 `python -m dashboard.screened_store --profiles <市场配置> --trials-root <连续研究根目录> --receipt-root <新的回执目录>`。当前仅授权美股独立数据库，默认连接数据库名必须核验为 `factor_miner_us`。

## 大文件清理与试验留痕

完成复核后，可以按明确清单清理未保留候选的可重建 `raw_factor.parquet`。先确认没有运行任务使用这些矩阵，且它们不属于后续基底或增量模型的冻结输入；登记删除前的路径、大小、内容摘要、候选身份和失败理由，完成后保存清理回执。只清理明确指定的运行目录，不自动扫描上游或历史副本。

必须保留 CandidateSpec、CampaignSpec、原始账本、运行配置、代码快照、数据版本引用、IC 序列、相关性结果、成交记录、筛选理由和 Dashboard 报告。清理记录独立追加，不重写原研究产物或缩减原统计检验族。日后重算被清理的矩阵需要原数据版本与冻结代码，不再声称该运行仍保有全部计算矩阵。

例如本轮 45 个美股候选中，即使清理 29 个未保留候选的矩阵，本轮 Bonferroni 分母仍是 45。失败、重复和中断名额不能通过归档消失。后续批次按事前冻结的假设预算和检验族执行；不能通过新建批次或删除文件重置已经发生的适应性试验历史。

编译前失败也须保存原式、登记身份、失败日志与账本事件，消耗所在批次的预留名额。已评价候选数量与含编译失败的全部尝试数量应分别记录；不得为使数量相等而伪造缺失IC或交易结果。后续登记应查询这些失败公式，核验其账本并绑定文件内容，归档回执的累计试验数包含这些尝试。初次合成预检失败后补记的记录必须如实写明时间，不能倒填成预检前登记。
