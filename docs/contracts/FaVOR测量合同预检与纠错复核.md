# FaVOR测量合同预检与纠错复核

## 区分金融失败与合同错误

合成扰动的方向、观察量与候选值的关系、候选与未来收益的预期方向，是三个不同概念。修正合成测试方向不能自动翻转因子的预期收益方向，也不能把旧失败改成通过。

例如价格持续接近历史低点时，`close / rolling_min(low)` 应下降，而其倒数应上升。若前一种测量的观察合同要求上升，属于起草错误，不能据此认定价格锚机制无效。

`preflight-favor` 在候选生成前检查事前状态锚的结构和合成响应，仅读取计划及合成数据，不打开真实行情或收益，不消耗候选槽或登记研究。状态锚与候选值单调反向时，显式镜像所需合成响应。检查失败不会自动修改合同；须解释代理差异或在提交前重新冻结。通过也不替代候选本身的构念和收益检验。

```bash
factor-miner preflight-favor <计划.json> <不可覆盖的预检结果.json>
factor-miner register-favor <计划.json> <新运行目录>
factor-miner favor-request <新运行目录> <槽位> <请求.json> --producer gpt6
```

提交必须引用新运行目录内的已登记计划或官方请求里的 Γ，不能猜测配置文件名。存在 `plan_v2.json` 时，读取旁边的旧 `plan.json` 会导致错误提交；Γ继续拒绝不符公式，不能为了执行成功绕过检查。

## 有上限的纠错复核

十五因子目标首轮四十八槽全部保留且已消费。H03一个槽误读旧算子结构，H09两个槽合成响应方向错误；本次只针对这两个已列明联合主张，登记八个复核槽、160个模型名额。继承153次历史尝试及15157倍诊断预算，新分母15325。原失败不释放预算，复核不是八个新经济机制或新发现。

原主张、预测方向、可观察状态、窗口集合、收益标签、分区、构念覆盖、三档选择性、联合支持比例及成本全部保留。H09只改合成扰动预期响应；H03使用原本已登记的正确算子结构。全部复核仍使用已消费历史，不恢复样本外身份。

为了重验同一测量，目标公式可以显式列为历史身份重验对象，不以其既有AST身份直接跳过本次计算。完整历史哈希集合、仅对本次复核适用的目标哈希例外、旧槽到新槽的映射必须绑定到计划输入哈希。其余历史重复仍按原规则处理；复核结果不得作为“从未尝试过”的新因子数量。

先进行合成预检并冻结完整修正计划，再走官方登记、请求、提交、评价及账本验证。两项复核各自完成后即封存，不按收益结果继续改方向、阈值或窗口。同一结构问题的预检不替代新财务信息来源，也不构成无限扩预算的理由。
