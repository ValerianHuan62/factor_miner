# 联合诊断代表库采纳

用户可显式采纳已完成联合诊断的代表清单作为日常研究输入。采纳不产生新因子、不恢复历史统计预算，不改变原候选的待正式确认资格，也不将参考收益转换为实际收益。

## 发布与输入合同

- `factor-miner adopt-joint-library STUDY OUTPUT` 校验完成产物哈希与完整成员覆盖，向全新目录写入不可变 `library.json`、完成回执和小型诊断快照。
- 每个成员保留稳定编号、原候选身份、原方向、机制、原矩阵与 Spec 位置。每个替补必须直接映射到同机制的研究代表。
- `factor-miner list-joint-library OUTPUT` 默认仅输出代表，供后续任务显式选择输入；`--include-reserves` 用于查询完整档案。已有冻结运行的输入清单不被自动改写。
- 采纳不复制或删除原矩阵。新的任务使用代表清单时可减少加载与计算；历史复现产物保留，因此采纳本身不释放既有矩阵的磁盘空间。
- 完整诊断留在原运行目录，采纳库保存日常查询所需的小型快照，不依赖原 Worktree 才能读取成员。原累计候选库仍是指标主存储。

## PostgreSQL 与界面

`factor-miner publish-joint-library OUTPUT --dsn-env NAME` 只写成员版本表 `factor_library_members` 和当前版本指针 `factor_library_active`。先核对已有稳定编号及待确认资格，在同一事务中验证完整成员后切换版本。旧版本和原候选指标不改写，不向正式统计因子表插入候选。

Dashboard 的 A 股 profile 显式配置 `joint_library_path` 后默认展示研究代表，支持替补与全部视图；未配置的市场保持原行为。基础指标继续读取已发布累计候选库。

## 验证

合成回归覆盖默认输入精简、完整角色映射、重复采纳拒绝、源产物篡改拒绝、跨机制映射拒绝、跨市场拒绝，以及界面保留原统计状态和实际收益空值。真实入库回读核对代表数、替补数、稳定编号和原候选表未变化。
