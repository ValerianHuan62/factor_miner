# V0.5 单候选在线试运行合同

## 1. 金融研究过程

本流程先寻找现有因子库覆盖较少的金融方向，再让三个固定角色依次完成经济假设、数学表达式和语义一致性检查。模型不能读取真实因子、公司行情、个股、精确 IC、完整相关矩阵或既有候选结果。

一次试运行的金融顺序是：

```text
脱敏覆盖空白或纯公开研究主题
→ 公开文献元数据检索
→ 冻结经济主张、竞争解释和证伪路径
→ 人工批准假设
→ 生成三个预留槽 AST
→ 固定程序检查字段可得性、单位、时序、前视和编译
→ LLM semantic lint 只批准或拒绝
→ 冻结 120 槽 generation seal
→ 公司服务器计算原始因子
→ 5 日开盘到开盘 RankIC、HAC、Bonferroni、冗余和残差增量评价
```

试运行只需要展示一个候选样例，但统计分母仍是事前冻结的 120。没有实际生成的槽必须写入明确未执行终态，不能删除。这样得到的正向结果不会因为“这次只看一个”而获得虚假的宽松显著性。

即使候选通过可见评价，也只能称为“通过可见验证的候选因子”。它不是密封样本外证据，不能证明经济机制成立，也不能自动进入生产因子库。

## 2. 三个角色

### 2.1 经济学假设代理

只能读取公开/脱敏 payload，并且只拥有 `search_literature`。该工具由固定程序转为 Crossref 元数据查询；模型不能提供 URL，程序不抓网页正文，也不跟随 Crossref 结果中的 URL。

### 2.2 数学表达式代理

只能读取已经人工批准的假设、公开字段别名、白名单算子和三个候选槽。它没有工具，不能访问网络、文件、终端、行情或评价结果。

### 2.3 语义一致性代理

只能读取冻结假设和已经通过固定程序编译的公开别名 AST。它只能批准或拒绝，不能修改公式、假设、预算和评价政策；其结论没有独立证据权重。

## 3. 外发与密钥边界

正式请求固定使用：

```text
endpoint = https://api.deepseek.com/chat/completions
model = deepseek-v4-pro
thinking.type = enabled
reasoning_effort = high
stream = false
response_format.type = json_object
```

每次请求先生成不可变 JSON，再运行公司政策和敏感信息扫描。操作者必须先执行 `export-preview`，核对请求 SHA-256、信息类别、模型和预算，然后把同一个哈希输入 `authorize-export`。工具 continuation 是新请求，必须重新预览和授权。

公司外发政策本身也采用内容寻址，必须冻结官方 endpoint、允许模型、信息类别、最大 campaign 数、有效起止时间、匿名公司批准角色和可核验批准引用。政策过期、内容被修改、角色不符或哈希不一致时，即使操作者刚刚点击请求哈希授权也不能发送。个人点击不能替代公司政策。

`DEEPSEEK_API_KEY` 只从公司 Linux 当前进程环境读取。CLI 没有密钥参数，录制文件、异常和标准输出均不保存密钥。可在服务器交互式 shell 中无回显输入：

```bash
read -s DEEPSEEK_API_KEY
export DEEPSEEK_API_KEY
```

不得把密钥写入仓库、命令历史、JSON、`.env.example`、聊天或验收文档。

## 4. 操作顺序

以下路径均为服务器私有路径，不进入 Git。

### 4.1 构建公司外发政策

部署责任人先在服务器私有 `corporate_external_policy_spec.json` 中填写设计规定的政策字段，但不填写 `policy_id` 和 `policy_sha256`。其中 `approver_role` 只能写匿名公司角色，`approval_reference` 必须指向可核验的公司批准记录，不能把个人点击当作批准引用。

```bash
uv run factor-miner llm policy-build \
  corporate_external_policy_spec.json \
  --output corporate_external_policy.json
```

程序会核验官方 endpoint、唯一允许模型、正向有效期和内容身份，并生成不可变政策文件。

### 4.2 准备假设代理请求

```bash
uv run factor-miner llm request-prepare \
  hypothesis \
  public_payload.json \
  --campaign-id <已登记 campaign ID> \
  --slot-ids hypothesis_slots.json \
  --output hypothesis_request.json

uv run factor-miner llm export-preview \
  hypothesis_request.json \
  corporate_external_policy.json
```

人工核对预览后：

```bash
uv run factor-miner llm authorize-export \
  hypothesis_request.json \
  corporate_external_policy.json \
  --approved-request-sha256 <预览中的精确请求哈希> \
  --approver-role research_owner \
  --output hypothesis_authorization.json

uv run factor-miner llm provider-call \
  hypothesis_request.json \
  corporate_external_policy.json \
  hypothesis_authorization.json \
  --record-root <服务器私有录制根目录>
```

若返回 `tool_call_count > 0`，先用冻结公开词表解析：

```bash
uv run factor-miner llm literature-resolve \
  hypothesis_request.json \
  <调用录制目录> \
  allowed_literature_vocabulary.json \
  --output-request hypothesis_continuation.json \
  --literature-root <服务器私有文献记录目录>
```

新的 continuation 必须重新运行 `export-preview`、`authorize-export` 和 `provider-call`。直到 `has_final_json=true` 后：

```bash
uv run factor-miner llm response-validate \
  hypothesis \
  <最终调用录制目录> \
  --output hypothesis_drafts.json
```

此处必须暂停，等待人工核验来源、竞争解释和证伪路径。程序不得自动批准假设。

### 4.3 表达式与语义审查

人工批准并登记假设后，分别以 `expression` 和 `semantic_lint` 运行相同的请求准备、预览、授权、调用和响应验证过程。两者的请求不会包含 `tools`。

合法输出可以转换：

```bash
uv run factor-miner llm candidate-convert \
  candidate_batch.json \
  lint_batch.json \
  registered_hypothesis.json \
  field_registry.json \
  candidate_provenance.json \
  --candidate-slot-id coverage_outcome_llm:C001 \
  --output trusted_candidate_spec.json
```

转换会从 AST 推导真实字段、最大回看、单位、最早决策和最早交易时点，并立即运行既有 DSL 与编译器。模型自由声明的字段、lookback 或 availability 不会被采用。

### 4.4 登记、封存和评价

可信候选继续使用既有候选、研究族和 campaign 登记入口。所有 120 槽形成终态后运行 `family-seal`；评价器必须核验 seal 和数据时间关系。严格时间留出要求评价依赖的最早原始观测晚于 discovery context 最晚信息时点，并包含因子 lookback 与 5 日标签边界。

## 5. 当前可运行边界

本合同对应代码已支持：

- 固定三角色请求；
- 精确请求预览和限时哈希授权；
- 密钥安全的 DeepSeek 发送；
- 原始请求与响应的不可变录制重放；
- Crossref 工具调用及 continuation 再授权；
- 三类响应 Schema 核验；
- 字段 point-in-time、单位语义和可信候选转换。

服务器真实调用仍要求部署责任人提供有效的服务器私有公司外发政策、公开词表、字段注册表和 `DEEPSEEK_API_KEY`。缺少任何一项时必须停止，不能自动创建一份声称已经获得公司授权的政策。
