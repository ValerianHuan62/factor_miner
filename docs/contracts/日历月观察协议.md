# 日历月观察协议

股份变化等慢变量需要明确的日历月观察。信号频率、公式观察跨度与预测收益期限是三个独立的选择。本协议允许精确定位过去月末，不把十八个月近似为固定交易日数，也不改变既有统计门槛。

## 观察定义

`calendar_month_delay` 只接受一个原始字段，`period` 的单位是日历月。显式新协议允许的偏移为 1、6、7、18；每个候选实际使用哪些偏移，仍由结果揭晓前冻结的 Γ 决定。窗口变体继续占候选名额。

给定信号日，先从完整、显式市场日历确定目标月份的最后一个交易日，再精确连接该证券当天的字段。证券缺少该行、字段未知、或日历未覆盖目标月份时返回空值；不得寻找更早报价。当前月内所有信号使用相同的历史月末端点，目标月份必须严格早于信号月份。

市场面板不得自行提供保留的月末索引列。历史字段必须使用同一发布、同一单位和可比较调整口径；拆股累计调整遇到未知事件时，数据适配层必须保持未知，不能把它当作乘数一。此算子不验证供应商数据是否保留了原始公布版本，滞后观察也不能证明这一点。

## 版本与复杂度

- `favor-gamma-v3` 显式绑定 `hypothesis-gamma-calendar-month-v1` 及候选 `spec_version=3`，使用原来的登记、提交、运行 CLI。
- v1、v2 默认值、规范序列化和 Γ 身份保持不变；旧版本拒绝月度观察。
- AST 仍最多十五个节点、五层深度。普通日频分支仍限制 130 个观察，原滚动窗口白名单不变。
- 月度算子只能直接读取原始字段；其结果不得再次嵌套滞后或滚动算子。允许通过普通算术组合已经冻结的月末观察。
- 月度观察的 `lookback` 以每月 31 个市场观察的保守上界记账，十八个月上界为 558。这是预热跨度元数据，实际计算必须使用日历端点。它不表示普通日频窗口已经放宽至 558。

## 构念与执行

股份月度变化和价格修复合成反例分别检验状态增强的响应、股份单位重标不变性，以及观察滞后隔离。合成检验继续通过同一个 `validate_construct` 入口调用，随后仍执行真实五分位构念检验。它们不证明回购、发行或价格修复的经济机制。

v3 继承[多期限执行协议](FaVOR多期限执行协议.md)的标签、HAC、多条件 AND、三档方向选择性和成本定义。FaVOR 内部仍是固定持有；真实月末差额调仓使用另行冻结的[月末目标差额执行](月末目标差额执行.md)，不得混称。

工程回归覆盖跨年、闰年、节假日、缺失证券端点、预热不足、未来数值扰动、拒绝隐式升级、普通窗口与深度限制、两个合成构念及新版本完整工作流。工程通过不增加任何真实候选资格。

## 股份历史发布

`publish-share-observation-release` 从显式字段映射读取股数、有效区间、ADR 状态及股份事件乘数。股数单位为千股；每个事件以证券、除权日、事件序号去重，冲突硬失败。调整只接受事前定义的普通无事件、单现金、单拆股和现金加拆股结构；价格复权系数不充当股份乘数。

本版用每只证券首次有效观察作为比例基准。此后要求市场日历连续、非 ADR 股数有效以及事件可解释；任何断链之后的调整股数永久为空，不重新起算后跨链比较。该保守规则可能损失覆盖率，必须保留并报告，不能看收益后换规则。

基础发布之前新增的行只提供股份观察，OHLC 等基础字段为空、全部布尔状态为假；原基础行情和状态保持一致。标签与终值只复制冻结字节，发布器不读取收益数值。供应商年度历史修订以及缺少原始公告版本的限制继续保留。
