# 标准面板数据合同

## 研究边界

数据接入只解决“系统能否按冻结协议计算和审计”，不证明数据质量足以支持 Alpha 或实盘。不同市场的停牌、退市、交易时段、公司行动和复权语义必须由数据提供者明确处理，系统不会根据市场名称猜测。

## 三张标准表

行情表 `market.parquet` 的主键是 `date, asset`，必需列为 `open, high, low, close, volume`，可选列为 `amount`。价格必须为正，成交量不得为负，主键不得重复。

状态表 `state.parquet` 与行情键集合完全一致，必须包含以下 Boolean 列：

- `valid_for_factor_compute`：该记录可参与原始因子计算；
- `valid_for_factor_rank`：该记录可参与当日截面排名；
- `valid_for_trading`：该记录满足冻结组合协议的交易条件。
- `can_open_long`：该交易日开盘允许新增长仓；
- `can_close_long`：该交易日开盘允许平掉已有长仓。

`valid_for_trading` 只作兼容性汇总状态，不能替代买入和卖出两个执行状态。A 股适配器可从显式 `can_buy/can_sell` 映射；其他市场必须由市场适配层直接提供，核心系统不猜测。

标签表 `label.parquet` 与行情键集合完全一致，必须包含 `label_entry_date`、`label_exit_date` 和 `label_o2o_5d`。默认标签按统一市场交易日历计算 `open[T+6] / open[T+1] - 1`；证券在固定入场日或退出日没有合法价格时标签为结构性 null，禁止改用该证券自己的下一条记录。

训练或发现区间若后接验证/确认区间，必须登记 `next_split_start`，并只保留 `label_exit_date < next_split_start` 的监督样本。`label_exit_date` 为空或触及下一分区的样本都要 purge，并记录移除行数和信号日数。

## 跨市场映射

A 股适配器可额外保存 `is_st, is_newly_listed, is_suspended, can_buy, can_sell`，系统会据此复核三类 mask。美股或其他市场不需要伪造这些 A 股字段，但必须直接提供符合当地规则的三类 mask。

## 发布身份

正式发布必须记录 release ID、三表 URI 与 SHA-256、源文件哈希、Schema 版本、市场截止日、复权口径、交易日历版本、状态表版本和截止日。运行配置还必须绑定 Git commit 与配置哈希；数据目录和运行产物目录不得重叠。

## 本地导入

`factor-miner data prepare-local` 可将标准 CSV 或 Parquet 转为三表发布。缺少 mask 时必须显式使用 `--assume-tradable`；该选项只适合已确认全体记录可交易的样本或演示数据，不能替代市场状态治理。标准发布版本为 `standard-panel-v2`，旧 v1 标签不得继续用于训练、方向选择或正式评价。

QuantLake、商业数据库或自建数据湖都可以作为上游，但都不是核心包依赖；适配结果满足本合同即可。

## Nasdaq成交笔数观察

`publish-observation-overlay` 通过显式源列映射追加 CRSP 同日 `trade_count`，版本为 `nasdaq-trade-count-overlay-v1`。数据在收盘后使用，年度历史修订不视为逐日供应商版本。数值必须为非负整数，未知和非法笔数保持缺失；零笔数是已知观察，不由未知补零。数据定义参见[CRSP字段指南](https://www.crsp.org/wp-content/uploads/2023/09/Sift_guide.pdf)。

此版本仅研究信号当日 `primary_exchange=Q` 且原本可排名的股票，适用范围必须单独展示。交易所身份缺失硬失败，不能按今天或未来的上市地回填。原始价格、计算状态、可买可卖状态和固定标签不变；转板后仍按原成交状态退出。原八基线与新增模型在同一Nasdaq共同股票池重新排名和拟合，不能直接用全市场基线作对照。

追加观察不等于观测了主动买卖方向、散户人数或订单流；经济机制未被独立验证时保持 `mechanism_unverified`。发布复用已有标签、日历和终止事件，新增市场与排名状态各保存一份并记录父发布哈希。

## 终止回收的持仓单位

终止结算表必须包含 `terminal_value`，原始 `cash_amount` 或退市收益率不能直接传入组合引擎。`publish-terminal-recoveries` 使用同一冻结发布中事件日之前最后可退出日的调整后收盘价：有效退市收益率对应参考价乘以一加退市收益率；有效每股现金对应现金乘以该参考日的股份调整因子。事件日当日及未来价格不作为参考。该方法沿用已登记的历史结算口径。

只向引擎发布可得日明确、回收金额非负且有限的事件；缺少依据的事件单独保存在未知表，不补零。实际回测仍按事件及可得时点处理回收，未解决持仓不能被这些未知记录升级为已结算。旧的错误发布和失败运行必须保留，并由独立修正发布绑定新的哈希。

`repair-favor-terminals` 只接受未完成且明确因终止结算合同失败的运行，绑定已完成的回收发布，在独立目录重放同一试验。原候选身份、公式、Γ、比较预算和完整失败链不变，追加带 `supersedes_event_id` 的纠错事件。它不是新的假设或参数变体，不产生第二份候选资格，也不释放失败名额；原结果目录保持不变。
