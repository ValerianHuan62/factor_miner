# 标准面板数据合同

## 研究边界

数据接入只解决“系统能否按冻结协议计算和审计”，不证明数据质量足以支持 Alpha 或实盘。不同市场的停牌、退市、交易时段、公司行动和复权语义必须由数据提供者明确处理，系统不会根据市场名称猜测。

## 三张标准表

行情表 `market.parquet` 的主键是 `date, asset`，必需列为 `open, high, low, close, volume`，可选列为 `amount`。价格必须为正，成交量不得为负，主键不得重复。

状态表 `state.parquet` 与行情键集合完全一致，必须包含以下 Boolean 列：

- `valid_for_factor_compute`：该记录可参与原始因子计算；
- `valid_for_factor_rank`：该记录可参与当日截面排名；
- `valid_for_trading`：该记录满足冻结组合协议的交易条件。

标签表 `label.parquet` 与行情键集合完全一致，默认标签列为 `label_o2o_5d`。标签必须由独立步骤生成，不能进入原始因子计算。

## 跨市场映射

A 股适配器可额外保存 `is_st, is_newly_listed, is_suspended, can_buy, can_sell`，系统会据此复核三类 mask。美股或其他市场不需要伪造这些 A 股字段，但必须直接提供符合当地规则的三类 mask。

## 发布身份

正式发布必须记录 release ID、三表 URI 与 SHA-256、源文件哈希、Schema 版本、市场截止日、复权口径、交易日历版本、状态表版本和截止日。运行配置还必须绑定 Git commit 与配置哈希；数据目录和运行产物目录不得重叠。

## 本地导入

`factor-miner data prepare-local` 可将标准 CSV 或 Parquet 转为三表发布。缺少 mask 时必须显式使用 `--assume-tradable`；该选项只适合已确认全体记录可交易的样本或演示数据，不能替代市场状态治理。

QuantLake、商业数据库或自建数据湖都可以作为上游，但都不是核心包依赖；适配结果满足本合同即可。
