# Factor Miner 技术报告：可审计、跨市场的因子研究系统

本文是 2026 年 8 月批次的历史工程报告，保留原统计和结论，不代表当前候选库数量或系统使用主线。当前状态请读[当前流程与日常使用](当前流程与日常使用.md)。

## 摘要

Factor Miner 的目标不是自动宣布“发现 Alpha”，而是把因子研究变成一条可冻结、可失败、可恢复、可审计的工程链路：研究者或受控 LLM 先提出可证伪假设，系统再通过类型化 AST、确定性编译、真实数据计算、统计评价、组合诊断和不可变账本完成验证。PostgreSQL 与 Dashboard 提供可重建的只读投影，不替代正式研究产物。

本报告基于 2026 年 8 月 18 日至 8 月 26 日完成的 25 个自主研究批次，验证系统是否能稳定执行预登记研究协议并如实保留失败。报告只使用批次级聚合统计，不包含原始行情、证券明细、候选表达式、内部路径、数据库内容或密钥。

结论是：Factor Miner 已经具备稳定执行完整研究工作流的工程证据，但这些证据不能单独证明候选具有未来 Alpha。系统当前最有辨识度的能力是研究治理、失败记账、跨市场数据合同、结构与输出双重去重，以及有边界的研究记忆；完整轨迹策略优化、跨轨迹重组和自动组合调参不在当前结论范围内。

## 一、研究问题与结论边界

Factor Miner 回答三个问题：

1. 一个金融假设能否在读取结果前被完整冻结并转换为类型合法、无未来信息的因子表达式？
2. 候选能否在固定数据、标签、方向、统计预算和评价政策下完成可复验计算？
3. 成功、失败、重复和中断能否共同进入不可变事实记录，而不是只展示幸存结果？

系统输出只能称为“通过当前协议验证的候选因子”。确认期通过不等于未来样本外有效，统计显著不等于可交易，相关性也不等于经济机制成立。若数据发布身份、状态 mask、交易日历、复权口径、截止日或配置哈希缺失，系统按设计失败。

## 二、系统链路

```text
研究覆盖缺口与文献
        ↓
事前假设与证伪条件
        ↓
候选槽位预登记
        ↓
类型化 AST 校验与确定性编译
        ↓
标准面板上的真实因子计算
        ↓
冻结方向、RankIC、HAC 与多重检验
        ↓
冗余检查、组合与风险诊断
        ↓
不可变 JSON/JSONL 产物
        ↓
PostgreSQL 只读投影与 Dashboard
        ↓
脱敏研究记忆与下一轮生成
```

模型只接收脱敏的研究上下文、结构偏好和离散失败模式，不接收行情、标签、精确 IC、回测收益、证券明细或密钥。模型生成的表达式仍须通过与人工候选相同的 Spec、compiler、evaluator 和统计协议。

## 三、关键设计

### 3.1 事前冻结与失败占位

每个候选在读取标签、IC、p 值或输出相关性前，冻结主张、机制、预期方向、代理变量、竞争解释、失效方式、证伪路径、数据身份和评价政策。每个参数变体占用独立槽位；表达式错误、编译失败、重复候选和运行失败不会从多重检验分母中删除。

### 3.2 安全表达式层

候选只允许使用白名单类型化 AST。编译器检查字段、单位、节点深度、窗口和时点，禁止 `eval`、`exec`、动态导入、负向 shift、居中滚动、未来字段和未来填充。原始因子层不做缩尾、标准分、排名标准化、中性化或 `fillna(0)`。

### 3.3 数据与运行环境解耦

正式输入是满足标准面板合同的显式 CSV/Parquet 发布，而不是特定服务器、SSH、个人目录或 QuantLake。A 股、美股和其他市场使用同一核心流程，但必须各自显式提供可计算、可排名、可交易 mask、交易日历、复权口径和数据截止日。QuantLake 只是可选的 A 股适配来源。

### 3.4 不可变事实源与可重建投影

CandidateSpec、CampaignSpec、运行清单、评价结果和试验事件使用规范 JSON/JSONL 与内容哈希保存。PostgreSQL 只用于 Dashboard 查询，可由正式产物重建；数据库不可用不能被解释为研究事实丢失，也不能用数据库内容覆盖文件账本。

### 3.5 有边界的自进化

研究记忆汇总结构覆盖、离散失败模式和已接受的局部偏好，用于影响下一轮假设和表达式生成。配对局部变异影子层只在发现区间比较父候选与局部兄弟，并以连续时间区块一致性和经验下界决定是否接受结构偏好。它不改变主候选结论，不读取确认期选择变体，也不等同于完整 trajectory optimization policy。

## 四、端到端运行观察

服务器事实源共记录 25 个自主批次，全部到达 `completed` 终态。每批固定 10 个假设、30 个候选槽位和 Bonferroni 分母 30。聚合结果如下：

| 观察项 | 数量 | 解释 |
| --- | ---: | --- |
| 完成批次 | 25 | 全部到达终态，不代表每个候选成功 |
| 已批准假设 | 250 | 每批 10 个；本轮没有假设在人工审查层被拒绝 |
| 预登记候选槽位 | 750 | 每批 30 个，构成可见统计预算 |
| 完成评价 | 338 | 占全部槽位 45.1% |
| 失败槽位 | 412 | 占全部槽位 54.9%，继续保留在批次记录中 |
| 通过冻结确认门 | 239 | 占已评价候选 70.7%，不等同于未来 Alpha |
| 未通过冻结确认门 | 99 | 占已评价候选 29.3% |
| 配对局部变异批次 | 17 | 另有 8 个早期批次未记录该影子层 |
| 配对局部探针 | 48 | 24 个接受离散偏好，24 个放弃，无强行结论 |

单批运行耗时中位数为 3,489.896 秒，约 58.2 分钟；最短 554.118 秒，最长 71,262.078 秒。最长耗时是明显离群值，因此不能只用平均耗时描述系统吞吐。

上述数据证明的是：批次能够结束、预登记预算保持可见、失败不会从记录中消失、评价结果可以发布并进入后续只读投影。它不证明 239 个候选相互独立，也不证明它们在未观察市场、未来区间或扣除真实交易摩擦后继续有效。

本次聚合引用了 75 个既有 SHA-256 身份，并对排序后的身份集合计算摘要：


## 五、观察到的限制

第一，250 个假设全部通过审查，说明当前审查层更像格式与边界门，而不是具有明显淘汰能力的研究价值筛选器。后续应观察拒绝原因分布，但不能为了制造拒绝率而调整门槛。

第二，只有 338 个槽位完成评价，412 个槽位失败。严格失败有助于暴露 DSL、字段或表达式问题，但较高失败率也说明生成器与合法表达式空间仍未充分对齐。优化目标应是减少可预防的语法和单位错误，而不是删除失败记录。

第三，已评价候选的确认通过率为 70.7%，这个比例偏高，必须结合确认门定义、候选相关性和重复研究批次解释。它不能替代全新密封 OOS，也不应作为简历中的收益承诺。

第四，配对局部变异只形成离散结构偏好。它不是跨研究轨迹的 crossover，也没有学习“在什么研究状态下应采取什么动作”的显式策略。

第五，系统会诊断组合和风险，但不根据反复读取验证期表现自动搜索组合权重。该限制是为了避免把验证区间逐步训练化；若未来增加自动组合搜索，必须另设未参与搜索的密封评价区间。

## 六、与完整轨迹优化的关系

Factor Miner 已经把假设、表达式、编译、评价、反馈和发布保存为可重建研究轨迹，但当前主要对轨迹进行治理和反馈，而不是把轨迹本身作为策略学习对象。相比立即增加 crossover 或自动组合搜索，现阶段更重要的是用公开可运行的合成数据与脱敏聚合证据证明以下差异化能力：

- 结果揭晓前冻结研究主张、方向和统计预算；
- 失败候选仍占试验名额；
- 数据、代码、配置和运行产物具备哈希身份；
- 发现区间与确认区间职责分离；
- AST 结构冗余与真实输出冗余分别检查；
- PostgreSQL 可重建，文件账本保持事实权威；
- 研究记忆只接收脱敏、离散、受限反馈。

如果未来实现轨迹策略优化，最低要求不是“能变异和交叉”，而是预先定义状态、动作、奖励、可读区间、停止条件和独立最终评价区间，并确保策略搜索不能反复读取密封结果。

## 七、可复验方式

公开仓库不包含真实数据、私有运行配置或正式研究产物。任何用户都可以使用合成数据验证核心合同：

```bash
git clone https://github.com/ValerianHuan62/factor_miner.git
cd factor_miner
uv sync --frozen
uv run python -m unittest tests.test_synthetic_e2e -v
```

跨市场真实研究应先按[标准面板数据合同](contracts/标准面板数据合同.md)准备本地 CSV/Parquet 发布，再使用独立产物目录运行。公开合成测试证明代码合同成立；本报告的聚合观察证明一组真实批次曾稳定完成；二者都不替代用户对自身数据质量、市场状态语义和最终样本外结果的验证。
