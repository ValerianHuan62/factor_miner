# 项目目录与文件管理

## 金融研究边界

代码、测试、公开示例和数据合同进入 Git；真实数据、候选完整结果、账本、模型、密钥和服务器路径不进入 Git。移动或清理文件不能改变候选身份、试验预算、冻结方向或已经发布的研究事实。

## 文档先读哪一份

日常先读[当前流程与日常使用](当前流程与日常使用.md)，技术问题按[文档索引](README.md)定位。根目录 `README.md` 负责上手，`ARCHITECTURE.md` 负责数据流，`AGENTS.md` 只保留代理规则；具体参数放合同，完整真实结果放市场产物目录。

旧技术报告、旧筛选手册与决策保留为历史说明，不将其中的候选数量、成本门槛或研究目标自动套到当前代表库。通过导航区分用途，不因文档整理搬动已被冻结配置引用的文件。

## 文件归位规则

| 内容 | 位置 | 是否进入 Git |
|---|---|---|
| 核心算法和数据合同 | `src/factor_miner/` | 是 |
| CLI 合成回归 | `tests/` | 是 |
| 可公开的最小输入 | `examples/` | 是 |
| 无密钥配置模板 | `configs/` | 是 |
| 本机授权和一次性输入 | `configs/local/` | 否 |
| 中文研究说明和运行手册 | `docs/` | 是 |
| Skill | `skills/<名称>/` | 是，但不得成为运行时依赖 |
| 真实数据、账本、模型和报告 | 显式独立产物根；本机统一挂在 `artifacts/A股/` 或 `artifacts/美股/` | 否 |

## 本机市场入口

新增本机运行必须进入对应市场目录，不能继续在 `artifacts/` 顶层增加批次。每个市场的 `README.md` 保存当前资料位置和缺失项；实际标准发布、完整试验账本与预算必须逐项核验，不能用清洗数据、数据库导出或新建空目录冒充。

历史批次已经迁入市场目录。旧顶层路径保留隐藏的符号链接，供冻结配置、报告哈希和旧任务引用兼容；链接不复制数据。`.code_store` 是跨运行共享的代码快照，仍保留在隐藏目录。`markets/` 是隐藏的旧看板入口。文件浏览器显示隐藏文件或终端列目录时仍可能看到兼容入口，不要据此重复清理。

整理不改写历史计划和账本；本机可变的市场配置已使用新位置。上游行情目录只建立链接，不搬动或改写源数据。删除链接不会删除源数据，但不要沿上游链接执行递归清理。迁移回执保存在对应市场目录，记录新旧路径与保留文件哈希。

代表库采纳保存小型快照和成员映射，不复制全部因子矩阵，也不迁移完整联合诊断。若源诊断或 `replay_from` 缓存位于 Worktree，合并代码后仍是复现依赖；日常查询不依赖 Worktree，不等于完整复现也不依赖。迁移应另行核验引用，不能直接清理目录。

## 清理规则

可以直接清理的只有可再生缓存，例如 `.DS_Store`、`.pytest_cache`、`__pycache__` 和本地 `*.egg-info`。`*.local.json`、`artifacts/`、JSONL 账本、运行清单和来源哈希在确认引用前不得删除。

根目录不再放一次性 `*.local.json`。现有外部研究政策已归入 `configs/local/`，历史 V0.5 输入已归入 `configs/local/legacy-v05/`。

## 下游特征交付

`src/factor_miner/feature_export.py` 通过正式 CLI 将已采纳代表写入显式下游目录，生成版本化 Parquet 和来源清单。本机约定接收位置为 `huan_quant/pipeline/feature/`；这些真实文件不进 Git，不与研究账本混放。操作与数据语义见[因子宽表导出与模型接入](runbooks/因子宽表导出与模型接入.md)。
