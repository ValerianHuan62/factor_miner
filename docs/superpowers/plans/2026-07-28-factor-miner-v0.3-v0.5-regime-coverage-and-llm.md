# Factor Miner V0.3 至 V0.5 市场状态、覆盖图谱与受控假设生成路线计划

- 状态：V0.3 与 V0.4 已完成公司 Linux 验收；V0.5 技术设计已批准，离线协议核心已实现，在线受控调用待实施
- 日期：2026-07-28
- 前置版本：V0.2 增量信息评价

## 1. 目标与金融边界

这条路线解决三个连续问题：

1. 如何用当时可得信息形成稳定、可审计的市场状态日历；
2. 现有因子库已经覆盖了哪些经济方向、数学结构和实际信号模式；
3. 哪些方向覆盖稀疏，值得由 LLM 提出新的可证伪假设和受限 DSL 候选。

覆盖稀疏不等于存在 Alpha，历史表现聚类也不等于经济机制相同。LLM 只能提出研究建议，不能决定评价口径、打开标签、修改试验预算或把候选直接写入生产因子库。

版本按自然顺序推进：

- V0.3：构建走步式、正式运行期固定 `K` 的 HMM 市场状态日历；
- V0.4：消费冻结市场状态快照，确定性构建现有因子双层覆盖图谱；
- V0.5：使用冻结图谱快照驱动受控 LLM 假设生成；
- 后续版本：实现公共表达式 DAG、分层缓存、严格失效、统一 Benchmark、候选级恢复、调度和结构化研究记忆。

## 2. V0.3 走步式 HMM 市场状态

V0.3 使用 point-in-time 全市场收益、二十日实现波动率、对数相对成交额和上涨股票占比构造日频 Gaussian HMM。研究阶段比较 `K=2、3、4`、`expanding`、`rolling_5y`、`rolling_8y`、`diag` 和 `full` covariance；正式运行阶段人工批准并固定配置，每月只重新估计参数，不动态改变 `K`。

BIC 只是研究诊断。候选选择优先比较走步式样本外对数似然、跨月状态稳定性和经济区分度。月内只能输出 filtered probability，日期 \(t\) 收盘后的状态最早在下一交易日使用。跨月状态使用完整成本矩阵和 Hungarian algorithm 全局匹配；全部模型失败时输出 `unavailable`，不强制产生状态。

## 3. V0.4 双层覆盖图谱

### 3.1 数学形式层

每个因子节点记录：

- 规范 AST、表达式哈希和因子 ID；
- 原始字段、算子、窗口、回看长度和信号时点；
- 人工批准的因子类别、经济机制、可观察代理和预期方向；
- 标签期限、股票池、评价政策、数据版本和可见区间；
- 因子来源、父候选、变体关系和研究族。

结构边不能只使用自由文本分类。固定程序应分别计算字段重叠、算子子树重叠、窗口邻近、规范 AST 重复和人工类别关系，并保留每种关系的独立权重。

### 3.2 实际信号模式层

每个因子节点还应记录同一冻结评价口径下的历史表现摘要：

- 平均 RankIC、ICIR、正负方向占比和覆盖率；
- 分年以及预先定义市场状态下的 RankIC、ICIR 和稳定性；
- 与已有因子的原始输出相关性；
- 与已有因子的每日 RankIC 时间序列相关性；
- V0.2 正交化后的解释比例、残差方差比例和残差 RankIC；
- 失败原因、有效日期和最小重叠样本数。

每日 IC 相关性矩阵必须由固定程序在服务器逐因子对生成，不能由 LLM 计算，也不能把全部因子 IC 序列拼成矩阵后一次性调用相关函数。每一对因子必须独立完成日期交集、缺失、最小重叠、方向对齐和 Spearman 计算，并写入该对自己的诊断。只有标签、股票池、可见区间、可得时点和评价政策兼容的因子才允许进入同一矩阵。不同预期方向先转换为经济方向一致的 IC 序列，同时保留原始有符号相关性和绝对相关性，避免把公式符号翻转误判为新信号。

矩阵每条边必须记录：

```text
factor_a
factor_b
correlation
absolute_correlation
overlap_dates
evaluation_policy_id
data_release_id
visible_interval
```

重叠日期不足、缺失比例过高或评价身份不同必须标记不可比较，不能静默填零。

### 3.3 市场状态

V0.4 只读取已经登记且冻结的 V0.3 `RegimeSnapshot`，使用按信息可得时点对齐的 canonical filtered probabilities。状态模型、配置、映射政策、数据来源和版本都进入图谱快照身份。结果后为某个因子重选 `K`、重训模型或定制状态划分会放大数据挖掘偏差，禁止作为正式覆盖结论。

### 3.4 图谱产物

V0.4 产出内容寻址且不可变的 `CoverageGraphSnapshot`：

```text
coverage_graph_id
factor_nodes
structural_edges
signal_pattern_edges
regime_profiles
cluster_assignments
evaluation_policy_ids
data_versions
visible_cutoff
graph_algorithm
algorithm_version
random_seed
snapshot_sha256
```

聚类算法、距离函数、阈值和随机种子必须冻结。失败候选也保留在图中，但与正式参考库节点明确区分。

### 3.5 V0.4 验收

- 结构相同的因子进入同一结构簇；
- 公式不同但 IC 时间序列高度相关的因子形成强信号模式边；
- 公式相似但表现模式不同的因子不会被强制合并；
- 符号相反但经济方向相同的因子能识别为同类信号；
- 不兼容评价口径、短重叠和缺失严重时失败关闭；
- 修改任一因子、数据版本或评价政策都会生成新的图谱快照 ID；
- Mac 只用合成矩阵测试，真实图谱只在公司服务器构建。

## 4. V0.5 受控 LLM 假设生成

### 4.1 LLM 获得什么

LLM 读取冻结的图谱快照及其摘要，包括：

- 各数学结构簇的字段、算子、窗口和代表因子；
- 各实际信号簇的表现特征、市场状态差异和簇间关系；
- 覆盖稀疏区域、已有失败模式和参考库边界；
- 可用字段、白名单算子、窗口、时点和候选预算；
- 需要独立验证的经济机制和引用要求。

公司完整结果、个股数据和密封样本外信息不得发送给外部模型。完整图谱只允许交给经过批准的公司边界内模型；外部模型最多获得脱敏、聚合且通过导出审计的 `LLMCoverageBrief`。

### 4.2 LLM 必须先提出假设

LLM 不能直接自由编写 Python。每个建议先生成 `CoverageGapHypothesisSpec`：

```text
coverage_graph_id
target_gap
claim
economic_mechanism
observable_proxy
expected_sign
availability
independent_verification
competing_explanations
failure_modes
falsification_path
sources
proposed_fields
proposed_operators
```

固定程序完成 schema、引用、字段、时点和预算校验。通过后，LLM 才能在同一假设下提出有限数量的 `CandidateFactorSpec`，并由现有 compiler、evaluator 和账本处理。

### 4.3 防止自适应过拟合

- LLM 生成前冻结图谱快照、提示模板、模型版本、温度、随机种子和候选预算；
- 同一建议的所有公式、窗口和参数变体都占用 hypothesis slot；
- LLM 在一个批次生成完毕并登记之前不能看到该批次任何标签或 IC；
- 失败、中断和重复候选继续保留在研究族与图谱中；
- 图谱使用过的可见结果不能再被称为密封样本外证据；
- 下一轮只能读取新版本图谱快照，且必须记录上一轮全部结果；
- LLM 不得修改市场状态、统计协议、正交化政策和参考因子库。

### 4.4 从空白到候选的流程

```text
冻结现有因子与评价身份
  → 固定程序构建双层覆盖图谱
  → 形成内容寻址图谱快照
  → 生成受控 LLM 覆盖摘要
  → LLM 提出可证伪假设
  → 固定程序校验并占用研究名额
  → LLM 生成白名单 DSL 候选
  → 编译、冒烟、可见评价与 V0.2 增量闸门
  → 全部结果进入下一版图谱
```

### 4.5 V0.5 验收

- 相同图谱、模型配置和种子生成相同结构化建议，或明确记录不可复现边界；
- LLM 不能获得 outcome 工具、任意文件访问或 Python 执行权限；
- 每个候选可追溯到图谱空白、假设、提示版本和生成参数；
- 未登记候选不能读取结果；
- LLM 无法改变 DSL、评价政策、研究族预算或增量闸门；
- 外部导出不含个股数据、完整 IC 序列、完整相关矩阵或密封样本外信息；
- 生成候选仍只能成为“通过可见增量信息验证的候选因子”。

## 5. 后续实施边界

V0.3 与 V0.4 的设计、实现和公司 Linux 验收已经完成。V0.5 已批准的第三版设计和离线协议核心冻结了：

1. 公司边界内模型或外部脱敏导出的权限方案；
2. `LLMCoverageBrief` 的字段、聚合粒度和导出审计；
3. 提示模板、模型版本、温度、随机种子和可复现边界；
4. LLM 生成批次的预算和自适应研究治理；
5. 图谱更新频率以及历史快照保留规则；
6. 从覆盖空白到假设、候选和研究族的完整追溯合同。

离线核心已经实现双数据身份、严格时间留出、脱敏 brief、120 槽状态机、独立哈希链账本和不可逆 generation seal。下一阶段只接入受控 DeepSeek 调用、录制重放、人工授权、字段 availability、DSL semantic type 与公司 Linux 单候选试运行；不得绕过离线核心重新建立另一条生成路径。
