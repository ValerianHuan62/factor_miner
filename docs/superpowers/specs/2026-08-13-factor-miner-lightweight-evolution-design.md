# Factor Miner 轻量进化研究设计

## 目标

本次重构把现有面向 120 槽受控实验的复杂流水线，收敛为适合个人长期研究的轻量流程。系统继续约束未来信息、结果后调参和不完整评价，但不再把大量时间消耗在多层授权、重复身份校验和人工搬运上。

系统的默认产出仍称为“通过可见验证的候选因子”，不代表因果机制成立、未来仍有效或可以直接实盘。

重构后保留两种核心进化能力：

1. 研究记忆保存每一批成功、失败、重复和不可用候选的结构化摘要，为下一批选题提供依据。
2. 因子图谱保存公式结构、信号相关性、市场状态表现和研究覆盖缺口，帮助 LLM 避免持续挖掘同一类因子。

记忆和图谱只能影响下一批研究。当前批次一旦冻结，不能根据本批 IC、收益或 Sharpe 修改候选、参数或检验口径。

## 研究流程

默认流程为：

```text
上一版研究记忆与因子图谱
  → 生成中文研究简报
  → LLM 提出 10 个中文假设
  → 每个假设生成 3 个类型化表达式
  → 一次性冻结 30 个候选和评价政策
  → 服务器计算日频因子与分钟聚合因子
  → IC、RankIC、HAC、组合收益和冗余评价
  → 发布不可变研究产物
  → 投影 PostgreSQL 与 Dashboard
  → 追加本批研究记忆并重建下一版因子图谱
```

默认批次为 30 槽，但允许用户在运行前显式指定较小或较大的固定数量。系统不再强制四条生成路线各 30 槽，也不为了补齐预算自动生成候选。候选一旦读取结果便不能替换；失败、重复和数据不可用仍保留终态记录。

## 保留的五条硬闸门

### 禁止未来信息

日频信号使用当日收盘时已完整可得的信息，最早在下一交易日开盘交易。分钟聚合信号第一版也只允许使用完整交易日结束后的分钟数据，最早在下一交易日开盘交易。

负向位移、居中滚动、未来字段、未来填充、标签泄漏和未来状态继续硬失败。

### 结果揭晓前冻结

每批候选、方向、标签、股票池、评价区间、成本、HAC 参数和检验族规模在读取标签、IC、收益和输出相关性前一次性冻结。

### 核心指标完整

一个已评价候选只有在以下核心指标全部存在时才能进入 PostgreSQL 的完整评价视图：

- `ic_mean`、`rank_ic_mean`
- `ic_std`、`rank_ic_std`
- `ic_ir`、`rank_ic_ir`
- IC 与 RankIC 的 HAC t 值
- `win_rate`
- 年化收益、最大回撤、Sharpe、information ratio

缺失指标的旧运行、失败候选和未评价候选保留在审计记录中，但不伪造为零，也不混入默认完整评价列表。

### 参数变体计入本批检验族

同一公式的不同窗口、方向和条件都是独立候选，占用本批检验名额。统计显著性继续使用冻结 HAC 和 Bonferroni 校正，但不增加额外的企业级审批流程。

### 原始数据不外发

LLM 只接收字段目录、允许算子、覆盖缺口、中文研究记忆和脱敏统计摘要。原始日频或分钟级个股数据不进入外部模型请求。

## 简化内容

以下机制从默认主流程删除或合并：

- 四条路线必须凑满 120 槽的约束；
- 多层外发授权包和同一范围的重复审批；
- scope、policy、seal 和请求之间重复表达的身份字段；
- 表达式生成、语义检查、登记、封存之间的多个人工命令；
- 为同一运行提供多个功能重叠的恢复入口；
- Dashboard 投影阶段重复进行研究计算。

保留一个批次身份、一个冻结清单、一个追加式运行日志和一个最终发布清单。内容哈希只用于候选不可变性、运行产物完整性和记忆/图谱版本绑定，不为每个中间对象重复建立独立审批协议。

## 轻量命令入口

正式主入口设计为：

```bash
factor-miner research run \
  --config /data/factor_miner_artifacts/private_config/research.local.json
```

该命令负责：

1. 读取上一版记忆和图谱；
2. 生成或读取本批中文假设与表达式；
3. 执行本地白名单、可得性、未来依赖和重复检查；
4. 冻结本批候选；
5. 在 Linux 服务器计算和评价；
6. 发布完整产物；
7. 投影 PostgreSQL；
8. 追加研究记忆并生成下一版图谱。

中断后重复运行同一命令，系统从已完成步骤继续。默认不要求用户手工复制候选 ID、授权哈希或运行 ID。

## 研究记忆

### 保存内容

每个候选追加一条中文研究记忆，至少包含：

- `huanNNN` 业务编号和原始候选身份；
- 中文因子名称、金融主张、机制和失效条件；
- 规范 AST 哈希和结构标签；
- 数据频率、观察时点和最早交易时点；
- 终态：完整评价、重复、计算失败、数据不可用或未执行；
- IC、RankIC、HAC、覆盖率和组合摘要；
- 与已有因子的结构及输出冗余关系；
- 下一轮建议：继续探索、改变经济机制、补数据、停止该方向或仅保留为对照。

原始逐股票数据和完整逐日结果不写入记忆正文。详细结果仍通过不可变产物引用。

### 进化规则

下一批简报优先选择：

- 图谱中覆盖不足的金融机制；
- 历史上有方向稳定性但统计强度不足、且可提出独立变体的区域；
- 在不同市场状态有明显差异、需要条件化研究的区域；
- 分钟数据能够提供新观察代理，而日频字段无法表达的区域。

下一批应降低以下方向的优先级：

- 规范 AST 重复；
- 仅改变窗口的高相关变体；
- 多轮连续失败且没有新机制或新数据代理；
- 覆盖率不足或交易时点不可实现的设计。

LLM 不能仅因为某个历史候选收益高就复制或微调它；每个新候选仍需给出可证伪的事前主张。

## 因子图谱

现有 V0.4 双层图谱继续保留，并扩展频率标签：

### 结构层

结构层依据规范 AST、字段族、算子族、窗口族和数据频率建立关系。分钟聚合因子额外记录聚合窗口，例如开盘 30 分钟、尾盘 30 分钟或全日分钟序列。

### 信号层

信号层使用可见评价区间的逐日截面 Spearman 输出相关性。日频因子和分钟聚合日级因子可以比较，因为最终都形成资产—交易日的日级截面信号。

### 状态层

市场状态画像继续使用时点正确的 filtered probability。日期当日收盘形成的状态最早在下一交易日使用，不允许用平滑后的未来状态解释历史信号。

### 覆盖缺口

图谱为下一轮提供中文缺口卡，至少区分价格、成交量、流动性、波动率、日内路径、尾盘行为、开盘行为和跨频交互。缺口表示尚未充分研究，不代表该区域必然存在 Alpha。

## 分钟数据接入

第一版不做盘中下单和分钟级标签，而是把完整交易日分钟数据确定性聚合为日级候选信号。这样可以复用现有股票池、5 日标签、IC、组合成本和 Dashboard。

### 第一批聚合族

- 开盘前 30 分钟收益、成交额占比和波动；
- 尾盘 30 分钟收益、成交额占比和波动；
- VWAP 偏离和收盘价相对 VWAP 位置；
- 日内实现波动率和上下行波动不对称；
- 日内高低点出现时刻与价格路径；
- 分钟收益反转、趋势和成交集中度；
- 开盘、午后与尾盘之间的量价交互。

### 数据合同

分钟适配器只允许读取服务器已经聚合完成的正式目录：

```text
/data/quantlake/raw/market/minbar_h5/equities_final_2005_20260630
```

`minbar_h5` 下的回填目录、缺口补丁、尾部补丁和旧 `equities` 副本不是正式运行输入，不得自动扫描或作为兜底。适配器从上述唯一目录读取 HDF5 文件，并输出窄表：

```text
date, asset, intraday_feature_*, source_version, completeness_status
```

适配器必须明确：

- HDF5 key、列名和时间戳时区；
- 上午、下午交易区间和午休处理；
- 预期分钟数与缺分钟阈值；
- 停牌、零成交、重复时间戳和异常价格语义；
- 复权口径和与日频资产代码的映射；
- 数据截止日和版本身份。

不完整交易日不得用零填充伪造成完整分钟路径。分钟聚合结果写入独立派生目录，不改写 QuantLake 原始文件。

## PostgreSQL 与中文展示

PostgreSQL 继续作为可删除、可重建的 Dashboard 读模型。

候选业务编号全库稳定顺延为 `huan001`、`huan002`，同一 `source_candidate_id` 永久复用原编号。字段名、AST 算子、行情字段、哈希、运行 ID 和模型技术身份保留英文。

所有面向人的描述使用中文，包括：

- 因子名称、分类、计算方法、主张、机制、代理和失效条件；
- 预期方向展示为“正向”或“负向”；
- 可得时点展示为“当日收盘观察，下一交易日开盘使用”；
- 机制状态展示为“机制尚未独立验证”；
- 质量状态展示为“待评价”“评价完整”“计算失败”等；
- 来源展示为“人工”“LLM”“确定性对照”等。

数据库可以保留英文枚举作为内部稳定值，但 Dashboard 查询必须输出中文标签。为了避免同一 `huanNNN` 在多个历史运行中出现多行造成误解，默认视图只展示每个候选最新的完整评价；历史运行通过审计页查询。

旧的半空运行不删除。新增完整评价视图排除核心指标不完整的行，并在历史页明确显示“旧版评价不完整”。

## 代码边界与重构方向

重构优先拆分目前过大的模块：

- `cli.py` 只保留命令解析，把研究运行交给应用服务；
- `llm_orchestrator.py` 拆为简报、生成、校验和批次运行四个窄模块；
- `research_campaign_runner.py` 拆为冻结、评价和发布；
- `dashboard/pg_store.py` 拆为候选目录、指标、记忆和图谱投影器；
- 分钟数据使用独立适配器和聚合算子，不把 HDF5 细节塞进日频 `DataSource`。

现有不可变产物、记忆和图谱类型优先复用。删除的是重复编排和审批层，不重写已验证的 IC、组合、HAC、冗余和图谱算法。

## 失败语义

以下情况整批停止，且不投影半成品：

- 发现未来依赖或标签泄漏；
- 冻结清单与实际评价候选不一致；
- 分钟数据版本、时间戳或完整性合同不明确；
- 已评价候选缺少核心指标；
- 发布产物损坏或 PostgreSQL 投影与发布清单不一致。

单个候选公式非法、结构重复、覆盖不足或计算失败时，该槽记录失败并继续评价本批其他候选。系统不自动补抽替代候选。

## 测试与验收

Mac 只运行合成测试，至少覆盖：

- 30 槽默认批次和自定义固定槽数；
- 同批结果揭晓后不能修改候选；
- 日频和分钟聚合因子的未来依赖检查；
- 分钟缺失、午休、重复时间戳和停牌语义；
- 记忆只影响下一批；
- 图谱同时容纳日频和分钟聚合日级信号；
- `huanNNN` 全库顺延和重复投影复用；
- 中文展示映射；
- 旧半空运行不进入默认完整评价视图；
- 单命令运行、中断恢复和幂等投影。

公司 Linux 验收使用真实 QuantLake 和分钟 HDF5，只返回运行 ID、计数、哈希、失败码和聚合质量摘要。验收完成后，Dashboard 默认运行切换到最新完整批次。

## 非目标

本轮不实现：

- 分钟级盘中下单、冲击成本和逐笔成交模拟；
- 自动实盘发布或生产因子晋级；
- 在线根据当前批结果反复提示 LLM 调参；
- 删除历史失败、重复或半空运行；
- 把 PostgreSQL 改成研究事实主存储；
- 向外部模型发送原始个股日频或分钟数据。
