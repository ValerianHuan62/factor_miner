# 记忆辅助因子假设生成与因子谱图补强设计

## 研究边界

本设计把“历史因子进入记忆”和“下一轮针对覆盖缺口生成假设”接入现有正式研究族，
但不把回测结果解释为因果机制、有效 Alpha 或生产结论。每一轮研究仍必须先冻结假设、
数据身份、评价政策、统计预算和因子谱图快照，再读取本轮标签、IC、收益或 Barra 结果。

下一轮可以参考已经结束研究族的结构化摘要，但不能修改上一轮账本、补写上一轮事件、
缩小上一轮统计分母或自动批准新假设。所有真实因子计算和评价只在公司 Linux 执行；
Mac 只能运行合成测试和远程控制。

## 目标与非目标

### 目标

1. 每轮由固定程序根据最新已核验因子谱图和冻结的研究记忆，形成有针对性的覆盖缺口简报。
2. 每轮生成恰好 10 个候选假设；10 个假设必须经过人工批准后才能生成表达式和运行回测。
3. 每个批准假设生成恰好 3 个实质不同的 typed AST 因子设计。
4. 每轮完成后，把候选 Spec、失败、重复关系、评价摘要和覆盖关系写入追加式研究记忆，
   供下一轮建立不可变 memory snapshot。
5. PostgreSQL 提供可查询读模型，服务器 JSON/JSONL 仍是正式记忆和研究账本主存储。

### 非目标

- 不允许系统自动批准假设、自动进入下一轮或自动晋级生产。
- 不允许用只改变 `window`、`period` 或等价时序参数的表达式冒充三个不同因子。
- 不允许把本轮回测结果送回本轮生成提示，或让外部模型接收原始行情、个股面板、标签、
  IC、收益、Sharpe、回撤和 Barra 正文。
- 不实现删除、覆盖或静默修复研究记忆；更正只能追加新记录并保留旧记录。

## 现有输入的复用

设计复用 V0.4 已有的不可变覆盖图谱合同，不另建一套因子分类：

- `CoverageGraphManifest` 及其 `coverage_graph_id`；
- `factor_nodes.jsonl` 中的因子类别、子类别、字段、算子和 lookback；
- `structural_edges.parquet` 与 `signal_pattern_edges.parquet`；
- `cluster_assignments.json` 中的结构簇和信号簇；
- `factor_performance.parquet` 与 `regime_profiles.parquet`；
- `coverage_summary.json` 及逐文件 SHA-256 清单。

每次研究必须显式指定一个已发布的 `coverage_graph_id` 并完整核验 manifest，不能在运行时
含糊地读取“最新文件”。图谱中的历史性能只由服务器固定程序用于缺口优先级排序，不能
直接作为外部模型的数值输入。

## 核心对象

### 研究记忆条目

每个候选槽无论成功、失败、重复、未执行还是基础设施终止，都产生一个不可变的
`ResearchMemoryEntry`。条目至少绑定：

- `memory_entry_id`、`family_id`、`generation_seal_id`、`run_id`；
- `hypothesis_id`、`candidate_id`、`candidate_spec_hash`、规范 AST hash；
- 使用的 `coverage_graph_id`、`memory_snapshot_id` 和覆盖缺口标签；
- 字段签名、算子拓扑签名、时序角色、设计差异依据和 `design_policy_id`；
- 候选状态、失败原因、重复目标和可见评价摘要；
- 数据合同身份、记录时间、来源和条目内容哈希。

评价摘要可以保存在服务器正式产物和数据库读模型中，但不复制原始行情、逐股票面板、
完整日收益序列、模型请求响应正文或密钥。

### 研究记忆快照

`ResearchMemorySnapshot` 是某一轮生成前固定的条目集合及其内容哈希。它绑定：

- 参与的历史 `family_id`、`generation_seal_id` 和运行清单；
- 条目 ID 及条目 hash 的排序集合；
- 固定的截断规则、来源范围和快照生成时间；
- 用于缺口排序的记忆政策版本。

快照登记后不可原地修改。下一轮的 10 个假设请求必须记录该快照 ID 和 hash；快照变化、
图谱变化或政策变化都必须创建新的研究族。

### 覆盖缺口报告

`CoverageGapReport` 由固定程序从图谱和记忆快照生成，至少覆盖以下三类缺口：

1. 结构缺口：类别、子类别、字段组合、算子拓扑或结构簇覆盖不足；
2. 市场状态缺口：某一冻结状态画像下缺少可用、可比较或有明确失效记录的因子；
3. 数据可用性缺口：已有方向的字段长期无值、覆盖不足、常数截面或重复度过高。

历史 IC、HAC 和组合摘要只用于服务器内部对缺口排序，不直接改变候选评价政策，也不
作为外部模型的数字奖励。报告绑定图谱 manifest、记忆快照、缺口阈值和内容 hash。

## 运行流程

### 生成前冻结

固定程序依次核验图谱 manifest、研究记忆快照、公司外发政策、字段注册表、评价政策和
120 槽统计预算，生成新的 `family_id` 和 `ResearchEvolutionContext`。上下文至少包含：

- 10 个假设的总预算；
- 显式 `coverage_graph_id`、`memory_snapshot_id` 和缺口报告 hash；
- 两条 LLM arm 与两条 deterministic shadow arm；
- 每个假设 3 个设计、每个 arm 30 个槽、总计 120 个槽；
- 当前允许字段、算子、可得时点、最大 lookback 和失败语义。

上下文登记后，任何候选、IC 或回测结果都不能覆盖这些字段。

### 生成与人工批准

模型只接收脱敏的缺口简报、允许字段能力、允许算子、设计差异合同和避免重复所需的
结构化签名；不接收历史数值绩效或原始数据。固定程序要求输出恰好 10 个假设，并为每个
假设保存主张、机制、预期方向、可观察代理、独立验证、竞争解释、失效方式、证伪路径和
可核验来源。

人工批准绑定假设内容 hash、`family_id`、批准角色和时间。10 个假设未全部批准时，
流程停在批准闸门，不能生成 30 个主候选，也不能打开评价端口。

### 每个假设的三个设计

每个批准假设固定占用三个主设计槽，并为每个槽声明 `design_signature`。设计签名由以下
规范特征构成：

- 字段集合签名；
- 忽略参数后的算子拓扑签名；
- level、change、aggregation、interaction 等时序/组合角色；
- 节点数量、深度和输入组合形式。

生成前硬校验：

1. 三个规范 AST 必须唯一；
2. 任意两者不能只在 `window`、`period` 或等价时序参数上不同；
3. 任意两者至少有一个非参数结构轴不同；
4. 三个设计都必须通过同一字段、单位、可得性、lookback、未来函数和 typed compiler 校验。

不满足条件的候选仍占用原槽，并记录 `design_diversity_failed`，不能补抽新的候选。
通过生成校验后，仍需在 seal 后执行逐日截面 Spearman 输出相关性检查；高冗余候选保留
记录但不通过。

两个 LLM arm 复用同一批 10 个已批准假设，但使用不同的冻结生成路线；两条 shadow arm
只复用已经登记并通过固定编译的 coverage 父候选。四条 arm 合计 120 个槽，失败、重复、
未执行和基础设施终止都保留在统计分母中。

### Seal、评价与发布

120 个槽全部进入不可变生成终态后，固定程序从服务器本地对象重算 generation seal，
并绑定图谱、记忆快照、数据合同、设计政策、评价政策和统计预算。seal 前不得读取本轮
标签、IC、收益、组合、冗余或 Barra 结果。

seal 后继续复用阶段 A 的单一 Pilot evaluator，使用冻结 HAC、Bonferroni 分母 120、
组合、成本、CSI300 基准和可选 Barra 合同。评价结果发布为不可变 JSON/JSONL/Parquet；
随后投影 PostgreSQL 和只读 Dashboard。

### 记忆写入与下一轮演化

发布成功后，固定程序为全部 120 个槽生成研究记忆条目，并创建本轮结束摘要。下一轮开始
时先生成新的 memory snapshot 和 gap report，再生成新的 10 个假设；系统不会在本轮发布
后自动继续下一轮，也不会绕过人工批准。

记忆辅助的“进化”只改变下一轮的研究方向和重复规避约束，不改变本轮已经冻结的假设、
评价政策或多重检验分母。历史因子可以作为结构参考，历史失败和高冗余候选可以作为排除
约束，历史数值绩效只用于服务器内部的缺口排序。

## 数据流与存储边界

```text
已发布覆盖图谱 + 研究记忆快照
                 ↓
        固定缺口报告与演化上下文
                 ↓
      生成 10 个假设 → 人工批准
                 ↓
       每假设 3 个不同设计
                 ↓
        120 槽登记 → generation seal
                 ↓
      阶段 A Pilot evaluator 与发布
                 ↓
      120 条研究记忆 → 下一轮快照
```

服务器 JSON/JSONL/Parquet 是正式主存储，PostgreSQL 只保存可重建读模型。数据库中的
研究记忆表不得提供修改历史候选、批准假设、政策或账本的页面按钮；重复投影必须幂等，
数据库丢失后可以从正式产物重建。

## 失败语义与安全闸门

- 图谱 manifest、记忆快照、字段注册表、数据 release 或配置 hash 不一致：硬失败；
- 假设少于或多于 10 个、批准 hash 不一致或批准未完成：停在人工闸门；
- 三个设计出现 window-only 变体、AST 重复或设计签名冲突：原槽失败，不补抽；
- 120 槽未完整终结、对象 hash 不一致或 generation seal 缺失：禁止读取结果；
- 数据库投影失败：保留服务器正式产物，允许从清单重试投影，不回滚研究账本；
- 发现旧污染 family：只读隔离，禁止修复、继承、删除或作为记忆输入；
- 记忆条目缺少候选 Spec、失败原因、覆盖关系或数据身份：发布记忆失败并暴露错误。

## 验收测试

实现必须至少覆盖以下合成测试：

1. 只改窗口或周期的三个 AST 在生成前被拒绝；
2. 字段、算子拓扑或时序角色不同的三个 AST 可以通过设计差异闸门；
3. 规范 AST 重复和高输出相关性都保留失败记录且不缩小 120 分母；
4. 10 个假设未全部人工批准时不会生成候选或读取 outcome；
5. 图谱 hash 或 memory snapshot hash 变化会拒绝继续运行；
6. 120 个成功、失败、重复和未执行槽都能写入研究记忆并幂等重建数据库；
7. 外部模型请求不包含原始行情、标签、IC、收益、Sharpe、回撤或 Barra 数值；
8. 新一轮使用新 `family_id` 和新 snapshot，旧 family 与旧记忆字节保持不变；
9. 从正式 JSON/JSONL 删除并重建 PostgreSQL 读模型后，记忆 hash 和候选身份一致。

## 设计结论

本设计采用“结构化覆盖缺口 + 冻结记忆快照 + 人工批准 + 生成前多样性硬校验 + seal 后
输出相关性检查”的演化机制。它允许系统逐轮扩大研究覆盖面和减少重复劳动，但保留
研究者对假设的最终控制，并把每一轮选择、失败和结果限制在可重放的研究族边界内。
