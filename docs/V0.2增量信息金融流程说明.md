# V0.2 增量信息金融流程说明

## 一句话结论

V0.2 检查的不是“新因子本身有没有 IC”，而是“扣掉现有因子库已经包含的信息以后，剩下的部分还有没有 IC”。只有原始因子和剩余部分都通过冻结检验，系统才会称它为“通过可见增量信息验证的候选因子”。

这个结论仍然不是生产结论：它没有经过密封样本外检验、交易成本、容量、组合约束、CPCV 或 Deflated Sharpe Ratio。

## 为什么只看原始 IC 不够

假设已有因子库里有价值、质量和动量。一个新公式可能只是把这三个因子换了权重重新组合。它自己的 IC 可能很好，但没有给因子库增加新信息。

逐个计算相关性也不够。新因子可以和每个旧因子的相关性都不高，却被多个旧因子联合解释。因此 V0.2 保留三层检查：

1. 公式结构是否重复；
2. 新因子和每个旧因子的逐对截面相关性是否过高；
3. 完整旧因子空间能否联合解释新因子。

## 每天发生什么

对每个交易日，程序只看当天已经可用的信息：

1. 取当天可进入因子排名的股票；
2. 对新因子和参考因子分别做截面排名和标准化；
3. 用完整参考因子库解释新因子；
4. 把解释不了的部分记为残差；
5. 保存当天的覆盖率、样本数、矩阵条件、解释比例和残差比例。

可以把它理解成：

```text
新因子 = 已有因子能够解释的部分 + 新因子独有的残差
```

这一步不读取未来收益，所以不会为了得到漂亮结果而调整残差。

## 残差怎样接受检验

残差固定后，程序才打开未来五日收益标签。它对原始因子和残差分别计算：

- 每日 RankIC；
- 平均 RankIC 和年度稳定性；
- 处理时间相关性的 HAC 显著性；
- 按完整研究族尝试次数计算的 Bonferroni 校正；
- 方向是否符合事前假设；
- 效果量是否达到冻结下限。

V0.2 还要求残差保留最低限度的截面变化。如果残差几乎为零，即使数值上偶然出现 IC，也不能通过。

## 怎样解释结果

### 通过

表示在当前可见样本、当前股票池、当前标签和冻结线性参考库下，新因子有一部分不能被旧因子线性解释，而且这部分仍与未来收益排序显著相关。

正确名称是：

> 通过可见增量信息验证的候选因子

### 原始通过、增量失败

表示新因子自己看起来有预测力，但预测力可能主要来自已有因子库，或者独立部分太弱、不稳定、方向错误。终态是 `incremental_failed`，不能退回称为 V0.1 通过候选。

### 计算合同失败

参考覆盖不足、矩阵秩亏、条件数过大、参考库身份不一致等情况会硬失败。这不是“因子没有增量信息”，而是“本次数据不足以按冻结协议得出判断”。

## 仍然不知道什么

残差正交化只排除了冻结参考库的线性截面重叠，不能证明：

- 不存在非线性重复；
- 经济机制真实成立；
- 样本外仍有效；
- 扣除换手、冲击成本和交易限制后仍赚钱；
- 多个候选合成策略后仍有良好 Sharpe；
- 研究过程没有其他未记录的选择偏差。

因此 CPCV 和 Deflated Sharpe Ratio 仍然需要，但它们应当在形成组合和策略收益流以后使用。HAC 与 Bonferroni回答因子 IC 的时间依赖和多重尝试问题，三者不能互相替代。

## 产物里看什么

每个候选新增 `incremental_information.json`，重点字段包括：

- 有序参考基底；
- 参考库内容 ID；
- 每日正交化诊断摘要；
- 残差方差比例；
- 残差 RankIC；
- HAC 与 Bonferroni 结果；
- 是否通过以及失败原因。

候选包同时明确记录：

```text
visible_incremental_only=true
sealed_oos_used=false
production_eligible=false
mechanism_status=mechanism_unverified
```

这些字段是结论边界，不是免责声明装饰，任何后续系统都不得忽略。
