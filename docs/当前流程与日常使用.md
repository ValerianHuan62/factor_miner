# Factor Miner 完整流程与日常使用

Factor Miner 把论文线索转成可检验的假设，再生成公式并验证其预测力与交易表现。研究过程不能用回测收益倒推经济解释；最终候选始终携带原始资格与已经使用过的历史区间。

## 从研究问题到结果

| 阶段 | 主要工作 | 交付与判断 |
| --- | --- | --- |
| 论文与假设 | 核验来源，写明机制、方向、代理、竞争解释和证伪路径 | 事前经济假设；未经独立机制检验时保留未验证标记 |
| 可行性与登记 | 不读收益地核对字段、可得日、样本覆盖；冻结协议和预算 | 可计算的测量合同、不可变研究登记 |
| 公式与构念 | 将假设写成类型化 AST，并按冻结 `Gamma` 在不读取收益下检查五分位状态响应、覆盖与方向一致性 | 规范 Spec、结构身份、确定性计算计划；证明公式未偏离事前主张，不证明机制因果 |
| 原始计算 | 只读标准发布，按计算资格生成数值 | 原始因子矩阵，缺失保留；截面预处理另行执行 |
| 预测检验 | 按冻结区间计算 IC、RankIC、HAC 与多重检验 | 探索资格、正式确认结果与失败原因分别记录 |
| 交易检验 | 冻结持有期和成交规则，执行分组或组合回测及成本压力诊断 | 收益、回撤、换手和可实现性；未知终值单列 |
| 四层筛选与贡献 | Quality 后先以 Pearson/Spearman 与 MFCF 处理数值同质性，再用联合 Ridge 的逐因子删除重训 `ΔSharpe` 检查条件增量，最后以因果交易净 Sharpe 做机制组 Shapley | 代表和替补映射、条件贡献与经济贡献诊断；不改原资格，也不声称完整复现 SDF 或 SPPC |
| 结果交付 | 保存账本、报告、成员角色，发布界面并导出审核后的原始宽表 | 可追溯的研究结果和下游特征输入 |

## 入口如何选择

CLI 是正式研究入口，Dashboard 用于查看结果与受控研究交互。先运行 `uv run factor-miner --help` 查看命令，再按相应合同准备配置；无需依次执行所有研究模块。

- **校验公式**：`validate-spec` 和 `compile-spec`。
- **新探索**：`register-favor`、`submit-favor`、`run-favor`，默认遵循[探索与确认分层](contracts/跨市场探索入口与确认分层.md)。指定 FaVOR 联合确认使用对应协议，不能以探索入库代替正式通过。
- **既有候选诊断**：遵循[联合贡献诊断](contracts/既有候选联合贡献事后诊断.md)，冻结共同股票池、区间、成本和模型预算。
- **采纳及查询**：遵循[代表库采纳合同](contracts/联合诊断代表库采纳.md)，以 `list-joint-library` 查询默认代表；替补保留。
- **模型特征交付**：`export-joint-features`，见[宽表导出与模型接入](runbooks/因子宽表导出与模型接入.md)。
- **查看结果**：`make dashboard`。真实资料按本机 `artifacts/A股/README.md` 和 `artifacts/美股/README.md` 导航；公开仓库不包含私有结果。

## 结果之后的模型流程

已采纳代表 → 版本化原始宽表 → 对齐下游行情、状态与可得时间 → 冻结预处理和标签 → 构建 Dataset → 带标签事件 purge 的训练与验证 → 冻结预测 → 因果成交回测 → 独立评价。

原始特征导入只完成这条链的前两步。因子确认、模型验证和策略表现是不同层级；历史候选筛选已观察过的区间不能通过重新训练恢复样本外身份。

## 复现原则

候选、协议、数据版本、代码与配置身份都随运行保存。失败、中断和重复仍占用原研究预算；纠错追加新事件。JSON/JSONL 与运行产物是事实源，PostgreSQL 和 Dashboard 只读取或投影它们。

真实行情、候选全集、完整结果、模型和密钥不进入 Git。文档整理、结果查询和特征导出不会自动启动新挖掘或模型训练。
