# 因子状态分类与验证展示设计草案

日期：2026-09-09。状态：用户已批准；首版已实施。运行方式见[状态分类登记与展示](../runbooks/状态分类登记与展示.md)。

## 一、设计结论与首版范围

建议把“因子预期在什么状态下更有效、何时可能减弱、实际检验是否支持”纳入假设登记和 Dashboard。目标是让研究主张可以比较、可以被推翻，也能识别值得进一步研究的候选。

首版包含三项：新假设增加结构化状态说明；既有十二因子实验作为第一批状态检验记录；文件报告和 PostgreSQL 采用同一套展示语义。继续使用现有因子筛选与 FaVOR 协议，状态检验单独记录。

“预期在高压力时更强”不等于“其他时候应该关闭”。状态标签也不能直接证明资金流或风险承接机制。本方案借鉴条件假设与检验方法，不要求构造论文的 Q 或 BTQ。

## 二、用户看到的分类

### 列表增加两列

| 列名 | 回答的问题 | 展示规则 |
| --- | --- | --- |
| 预期适用状态 | 理论上什么时候更强？ | 短标签，如“高流动性压力”“趋势持续”；悬停显示完整主张 |
| 状态检验 | 数据是否支持这个主张？ | 如“待检验”“证据不足”“支持预期增强”；附“历史复核”等区间性质 |

原有“状态”列改称“筛选状态”，避免与市场状态混淆。原有经济类别和组合研究资格继续各自表达原含义。

以下为界面示意，不是真实检验结果：

| 因子 | 研究内容 | 预期适用状态 | 状态检验 | 筛选状态 |
| --- | --- | --- | --- | --- |
| 示例甲 | 短期价格反转 | 高流动性压力 | 证据不足 · 历史复核 | 沿用原记录 |
| 示例乙 | 趋势延续 | 趋势持续 | 待检验 | 沿用原记录 |
| 示例丙 | 尾部风险补偿 | 尚无明确条件假设 | 未开展 | 沿用原记录 |

默认表格不铺开长篇失效描述。点击因子后，详情卡展示：

1. **为什么可能有效**：引用原经济机制。
2. **预期何时更强**：状态名称、增强或专属等主张类型及理由。
3. **何时可能减弱或失效**：具体情形与因果理由。
4. **怎样推翻这项主张**：可以执行的比较与判据。
5. **检验发现**：全期、目标状态、对照状态的 RankIC，差值及置信区间，两组样本量、覆盖率和多重校正结果。

详情顶部同时写明市场、收益期限和检验区间；“历史复核”“此前已观察”直接可见。代码版本、文件摘要与内部身份放在折叠的研究记录中。首页和详情不显示未经检验的“当前应该启用”提示。

筛选器支持状态维度、预期方向和检验状态。CSV 导出包含这三项及假设来源、检验区间，避免脱离页面后丢失限定条件。

### 分类词汇与状态语义

首批状态维度沿用试验覆盖的流动性压力、波动、趋势持续性和交易活跃度。每个维度可以有高、低等明确方向；不同市场绑定各自的测量定义，不能只凭相同中文名称复用统计结果。

允许登记“尚无明确条件假设”，并说明原因。这表示没有提出状态差异主张，不能展示成“全市场状态有效”。未补充的旧因子显示“未登记”，与上述明确回答区分。

| 检验标记 | 含义 |
| --- | --- |
| 待检验 | 已有可检验的冻结主张，但尚无匹配结果 |
| 待数据 | 已写主张，必需代理数据暂不可得 |
| 样本不足 | 完成数据检查，但未满足冻结样本要求 |
| 证据不足 | 样本达到要求，但未支持预先声明的效应 |
| 支持预期增强 | 效应满足冻结的幅度、时间依赖与多重检验要求；限定于当前协议 |

“差值方向与预期相反”作为数值旁的说明，不凭负点估计自动判定机制错误。失效、等效和符号反转属于不同主张，需要各自判据；首版不设置笼统的“已失效”标签。

## 三、假设与 LLM 提示词

### 在生成公式之前回答状态问题

流程为：经济假设与状态主张 → 可观测性预检 → 冻结假设、测量和试验预算 → 生成公式 → 原有验证与独立状态检验 → 展示。

图片中“何时有效”的建议适合加入假设生成阶段。现有 `favor_generation_payload` 已经要求公式生成器遵守冻结假设与 Γ，因此公式阶段只能读取状态主张，不能重新编写它。人工、GPT 与 DeepSeek 共用相同要求。

建议新增以下提示词段落：

> 在给出表达式之前，说明这个机制是否预测可观察的状态差异。若是，选择一个主要状态，说明其作用渠道、信号产生时可获得的代理、预期增强方向，以及对照状态下的预期表现。区分“更强”“只有该状态有效”“符号反转”。写明会削弱或推翻这项状态主张的观测结果，并提出竞争解释。若没有依据，请明确回答“尚无明确条件假设”，不要为填写字段而创造叙事。只能使用登记允许的数据与测量定义，不得依据已有收益结果挑选状态。

以流动性反转为例，合格的表述是：

| 项目 | 示例内容，待登记验证 |
| --- | --- |
| 经济机制 | 流动性供给者承接暂时性卖压，价格随后回归 |
| 主要状态 | 市场流动性压力高，采用版本化报价价差代理 |
| 预期效应 | 沿冻结的反转方向，目标状态的 RankIC 高于对照状态 |
| 对照状态 | 压力较低，预期减弱；不预先断言收益消失 |
| 可能失效情形 | 价格下跌由持续的信息重估驱动，而非暂时性卖压；该风险未必能由市场压力代理识别 |
| 状态主张的证伪路径 | 在具有足够精度的独立比较中，增强幅度未达到事前声明的最小有意义差异，或显著反向 |
| 竞争解释 | 观察到的状态差异来自波动变化或样本构成，而非流动性承接机制 |

这里仅检验“流动性压力对应增强”的主张。对资金流和信息冲击的机制判断仍需独立证据。图片中“高波动／低流动性／高换手”不能作为一个含糊条件：首版每因子一个主要状态，其他状态只作为待研究说明。今后若检验联合条件，应事前写明 AND 或 OR，并计入预算。

### 独立的状态假设记录

现有 `HypothesisSpec` 已包含 `failure_modes`、`falsification_path` 和 `competing_explanations`。保留这些字段；新增记录细化其中的状态部分，避免维护两套相互冲突的经济故事。

拟新增版本化 `RegimeHypothesisSpec`，核心字段分为四组：

| 分组 | 主要字段与约束 |
| --- | --- |
| 主张 | 是否存在条件假设、状态维度与方向、完整主张、`stronger`／`exclusive`／`sign_reversal` 类型；首版主检验只支持 `stronger` |
| 测量 | 市场或个股层级、测量定义引用、字段与来源、观察时点、滞后、窗口、阈值和缺失规则；不可执行时明确原因 |
| 失效与比较 | 对照状态、预期减弱情形、证伪判据、竞争解释；引用原假设对应内容 |
| 登记身份 | 原假设摘要、市场、计划／条件／预留槽关联、来源类型、登记时间、结果是否已见、版本与内容摘要 |

首版可执行范围为市场时间状态；个股截面状态可登记文字，但不能误送进市场时间分组评价器。标签定义和测量定义分别版本化，不能修改公式后继续沿用原检验。

老因子采用独立追加记录，注明“历史补充假设”，不改写原始假设。新研究在接收公式前，把状态记录摘要绑定到新版研究计划及提交身份；公式产生后，再建立候选身份关联。新增状态定义或参数变体应显式登记，不能沿用已看结果的旧名额。

不能直接给旧 `HypothesisSpec` 添加默认字段后重存。Γ 当前校验其完整序列化内容的摘要，这种改法可能改变历史身份。采用独立记录及新版计划封装，旧版本保持原序列化与复现入口。

## 四、怎样形成有意义的检验结果

### 主要比较

固定原有方向，比较目标状态和对照状态的逐期 RankIC：

`ΔRankIC = 目标状态平均 RankIC − 对照状态平均 RankIC`

同时报告两组水平与全期结果。目标状态 IC 为正，只能说明该状态下存在预测关联；不能代替差值检验。

新检验在读取收益前冻结股票池、mask、收益期限、时间切分、状态算法、最小有效期数、最小有意义差异、HAC 参数、主要检验族和 Bonferroni 分母。这些数值由具体研究合同确定；展示功能不另设一套与既有实验冲突的通用门槛。

只使用决策时已知的数据构造状态，滚动阈值仅用历史窗口。缺失状态保持未知，不强行归入低状态；全未激活日期的 IC 不填零。多因子汇总保留时间对齐和因子间相关性，不能把十二个相关因子当作十二次独立证明。

“两个状态一样强”需要差值区间足够窄或预登记的等效检验。单纯差值不显著不能证明两者相等，也不能证明因子无效。

### 与筛选的关系

状态记录提供候选比较、分组研究和证伪依据。首版新增结果不改变原单因子通过状态、组合资格或机制验证状态；通过条件检验仍不能把 `mechanism_unverified` 自动改成机制已验证。

若以后要实现“只在某状态使用”，须单独比较全时使用与条件使用的组合表现，并考虑全未激活时段、覆盖率、换手及成本。原先 FaVOR 的构念测量与联合触发继续执行；新的市场状态比较不能冒充 FaVOR 构念通过，或未经登记改变其交易触发条件。

### 接入既有十二因子结果

使用已完成的十二因子、四机制家族比较作为首批展示验收数据，不为填表重跑研究。显示其真实假设来源、历史区间已消费状态和此前单因子结果已见标记；不足以支持增强的记录如实显示“证据不足”。

采用已核验、明确纠正先前时间排序问题的版本，并保留被替代记录。版本选择依据显式纠错关系和发布清单，不按更好的 p 值选结果。现有结果不满足的新判据显示“本次未评价”，不能追溯套用新规则宣称通过。

## 五、文件、PostgreSQL 与 Dashboard 的连接

### 文件仍是正式记录

在独立产物目录保存状态假设、检验报告和展示清单；新增或纠错通过追加版本及替代关系表达。原候选、试验账本和统计报告不原地修改。

展示清单为每个市场、候选和评价上下文指定当前展示的状态定义与运行版本。评价上下文至少区分收益期限、股票池和协议。不同上下文不能自动合并成一条“最新通过”；详情可以查看历史记录。

没有补充记录属于正常“未登记”；配置指向的记录损坏、身份不匹配或摘要不符属于明确的数据错误，不能静默显示未登记。

### PostgreSQL 增量投影

建议增加两个辅助表和一个查询视图，以下名称为拟定名称：

| 对象 | 职责 |
| --- | --- |
| `factor_regime_hypotheses` | 按市场、候选身份和状态定义版本保存主张；核心筛选字段使用普通列，完整说明保留 JSONB |
| `factor_regime_validations` | 按运行身份保存匹配的检验结果、区间、协议、样本量、效应与统计量，以及文件来源；允许同一主张多次检验 |
| `factor_regime_current` | 根据文件发布清单解析当前展示版本，每个市场、候选、评价上下文至多一行 |

继续通过 `(market_id, source_candidate_id)` 关联既有稳定 `huanNNN`。增加分类不重新分配编号；无法映射时明确报告，不能按行号猜测。兼容既有筛选因子、组合研究池与 FaVOR 结果，不强制候选必须先存在于美股筛选表。

查询界面通过明确上下文的 LEFT JOIN 获取 `expected_regime_label`、`regime_validation_status` 和 `failure_condition_summary`，实现用户可见的分类列。避免在多个基础因子表里各自维护一份状态真相。

迁移只增加这些对象及所需索引，不复用历史重建脚本。导入先验证全部输入，在事务中幂等投影；同身份内容冲突时失败。PG 发布失败只重试投影，不重新计算因子。数据库可由文件完整重建。

### 实际接入位置

| 现有位置 | 计划改动 |
| --- | --- |
| `src/factor_miner/schema.py`、`hypothesis_constraints.py` | 保留旧假设和 Γ 序列化；新增状态记录使用独立类型模块 |
| `src/factor_miner/favor_schema.py`、`favor_workflow.py` | 新版计划在公式生成前绑定状态主张；GPT 与 DeepSeek 请求共用 |
| `src/factor_miner/llm_hypothesis.py` | 假设提议阶段增加状态问题，并路由至同一登记合同 |
| `dashboard/library_review.py` 附近的文件叠加层 | 增加共用状态投影解析器，保留原报告指标 |
| `dashboard/results.py`、`factor_explorer.py`、`favor_page.py` | 两列、筛选器、详情卡及导出采用同一状态解释 |
| `dashboard/screened_store.py`、`src/factor_miner_pg/favor_store.py` 相关读取入口 | 接入辅助投影及明确上下文的查询，保持原身份映射 |

目前 `dashboard/results.py` 会直接加载文件报告，因此仅增加 PG 字段不能完成界面功能。共用解析器应同时服务文件和数据库展示，避免两处给出不同分类。

拟通过正式 CLI 提供状态登记、展示清单生成和 PG 投影入口；不是由 Dashboard 修改冻结记录。具体命令名在实施时与现有 CLI 命名统一。

## 六、实施顺序与验收

1. **记录与展示**：完成独立状态记录、共用解析器、PG 辅助投影和 Dashboard 列表／详情。接入既有十二因子记录，先验收展示是否准确。
2. **新假设入口**：修改假设提示词、新版计划与请求身份绑定，使后续假设在表达式之前登记状态说明；保持旧研究复现。
3. **后续研究**：需要新状态检验时，另行冻结有限研究比较。首版不因未检验标签自动发起研究，也不自动把标签变成交易开关。

验收重点：

- 旧候选、Γ、原筛选结果及数值逐项不变；新增状态记录不影响旧身份。
- 十二因子的主张、版本和检验结果均能按真实候选身份对应；不会显示成十二个已验证条件因子。
- 文件入口与 PG 入口的标签、样本量和统计结果一致；重复导入无重复行，联接不扩增因子行数。
- 未登记、无明确主张、待数据、样本不足和证据不足能准确区分；缺失不填零。
- 历史补充与事前登记明确区分；改变状态定义后不会继承旧版本的通过标签。
- 纠错后的发布版本生效，旧版本仍可追溯；不同市场、收益期限和股票池不会误关联。
- 新假设请求完整包含冻结状态主张；公式生成器不能修改状态；旧版计划继续复现。
- 页面能直接读懂预期与发现，内部摘要默认折叠；检查窄屏表格、筛选与 CSV 导出。

首版按本方案实现记录、展示和新计划绑定。新增条件收益研究及交易启停仍按独立冻结协议执行。
