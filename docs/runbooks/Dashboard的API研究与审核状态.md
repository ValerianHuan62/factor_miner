# Dashboard 的 API 研究与审核状态

A 股、美股共用论文与假设、测量登记、公式生成、统计检验及回测流程，分别使用各自的数据发布、交易状态、成本与评价分区。Dashboard 的 API 入口调用同一套 CLI，不设置另一套更宽松的因子通过标准。

## 使用顺序

1. 打开“设置 → 模型 API”，填写 DeepSeek API Key。当前复用项目已冻结的 DeepSeek 模型与官方端点；尚未增加其他供应商。密钥只写入本机 `configs/dashboard_api.local.json`，权限为 `600`，Git 忽略且不回显，留空保存会保留已有密钥；启动环境的 `DEEPSEEK_API_KEY` 优先。
2. 在侧栏选择市场。进入“挖因子 → API 研究 → 新建研究”，导入该市场的完整计划，或使用设置中指定的计划模板。中文表单可编辑论文来源、经济主张、机制、代理、竞争解释与证伪路径。
3. 核对测量、分区与预算后点击“校验并冻结本轮计划”。正式 `register-favor` 执行数据与测量预检、登记候选名额和代码身份。新增网页入口使用 `favor-exploration-v1` 与有限预算；失败不会自动放宽合同。
4. 在“研究任务”选择已登记计划，预览本轮研究内容与资源上限，点击“调用 API 并开始研究”。这一次操作授权向 DeepSeek 发送公开研究假设与测量合同，并在公式返回后自动运行冻结诊断，不需要继续在 Codex 对话框中操作。
5. 页面每五秒刷新阶段、候选进度、响应数量、输出 Token 与耗时；可请求停止后续阶段。关闭浏览器不会停止后台 CLI。完成后在“研究结果”查看探索与回测；已审核采纳的代表仍在“看结果”和“研究代表库”展示。

第一次接入仍需一份完整的数据与研究计划配置。此版 API 负责冻结假设之后的公式生成与诊断，不自动检索论文、核验引用或替用户创造测量合同。更换经济问题时须同步审查测量条件，不能只改假设正文、沿用不相干的旧代理。

## 审核与统计确认

“看结果”的 A 股已采纳成员明确显示“已审核 · 已采纳”或“已审核 · 同类替补”，并提供搜索、成员范围、因子详情和清单下载。代表库跟随侧栏市场，不再另设一个可能与侧栏冲突的市场选择器。

审核状态来自已验证的代表库成员映射，不改写源报告。“统计验证与收益口径”折叠区继续保留原始独立确认状态；这不是要求用户重复审核。未知实际收益仍保持缺失，参考收益不冒充已实现回报。没有代表库的市场显示明确空状态，不能拿另一市场的成员补位。

## API 执行与计量

`run-favor-api <运行目录> --market-id <市场> --plan-sha256 <计划身份>` 是后台入口。网页只负责验证当前市场路径、传递本机凭据环境并派发 CLI；不在页面刷新请求中执行长计算。

每个完整、尚未提交公式的计划最多派发一次。系统在付费调用前核对代码版本、数据身份和外发内容。每个请求保存精确授权、供应商响应及用量，然后交给原 `submit-favor`；公式错误仍占槽，不能被覆盖或释放预算。完成全部名额后才执行共同诊断。

资源上限来自冻结计划，不能在启动按钮中临时扩大。停止与累计时间检查延伸到诊断阶段边界，单次 HTTP 或 Polars 操作不被强行截断。供应商缺失用量、网络结果不确定或后台中断时保留记录并停止，不把未知用量当作零，也不自动重发。因子与统计失败不会通过重新命名目录消失。

本轮仅验证功能与合成研究链路，不自动进行真实付费调用、新因子探索、旧候选正式升级或模型训练。研究完成后的采纳和特征交付仍遵循[代表库合同](../contracts/联合诊断代表库采纳.md)与[模型接入说明](因子宽表导出与模型接入.md)。

## 运维

检查 `api/status.json`、`api/launch.json` 与逐候选调用记录；用户页面默认不显示这些技术细节。状态为运行但活动锁已释放时，页面提示后台中断；启动失败可展开启动日志。市场配置必须使用独立研究根目录，结果查询同时覆盖该市场显式配置的研究与历史产物根。

部署代码更新后应重启 Streamlit，确保新数据类和页面使用同一版本；仅刷新网页不能保证已加载的 Python 类被替换。数据、账本和后台研究进程不随 Dashboard 重启删除或重跑。
