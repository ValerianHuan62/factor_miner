# 状态分类登记与展示

状态分类记录“预期何时更强”及实际检验结果。原单因子筛选状态、组合研究资格、机制验证状态分别保留。

## 查看结果

“看结果”列表增加“预期适用状态”和“状态检验”，可按状态及方向筛选。因子详情展示可能失效情形、证伪办法、目标与对照 RankIC、差值置信区间、校正 p 和有效期数。因子探索页采用相同语义并支持 CSV 导出。

未补充的历史因子显示“未登记”。明确回答没有条件主张的因子显示“尚无明确条件假设”，不代表全状态有效。无显著差异不代表因子失效。历史复核与密封样本外分别标明。

## 新假设的登记

先从尚未提交公式的计划生成状态提议请求，供人工、GPT 或 DeepSeek 使用：

```bash
factor-miner regime-hypothesis-request <原计划.json> <新的请求.json>
```

请求只包含原假设、允许字段、观察条件和状态响应 Schema，不发送行情、个股数据或统计结果。状态说明必须在公式生成前完成；每个条件可提出一个主要状态，或明确说明没有条件主张。

将响应按 `condition_id` 写入新计划的 `regimes`，设置 `version` 为 `favor-regime-v1`。状态定义需要说明主张类型、测量代理、观察时点与滞后、阈值、对照、失效情形、证伪办法及竞争解释。缺数据可登记为待数据，但不能声称完成检验。

```bash
factor-miner register-favor <新计划.json> <新研究目录>
factor-miner favor-request --help
```

新版计划沿用日历月兼容 Γ 和原 FaVOR 执行协议。每次公式请求包含冻结状态及 `regime_sha256`，提交时缺少或替换摘要会记为失败尝试。完整计划内容摘要同时绑定所有状态，不允许结果后改写。通过编译后写入独立的 `regime_record.json`，候选本身仍保存原经济假设。

新真实研究必须使用新版计划。旧版只允许显式 `--legacy-replay`，既有已登记计划仍能加载和复现。合成演示可继续走旧版工程验证。新计划登记不会自动开展额外状态收益研究或修改交易开关。

评价阶段与提交阶段使用相同版本的提交格式，并再次核验 `regime_sha256`。
修复评价代码后，保留旧失败目录和冻结快照，使用原计划在新的运行目录重新登记、提交和评价；
原计划与候选身份不变时应单列为技术重放，不能删除失败或将重放计作新增经济假设。

`publish-favor` 为有稳定编号的保留候选同步生成待检验状态清单及辅助 PG 投影。公式提交阶段尚未分配业务编号的记录仅以候选身份留在文件中，不提前创建 `huanNNN`。

## 导入已经完成的状态比较

当前导入器支持 `state-hypothesis-batch-v1` 的高状态增强比较。它核验完成标记、产物摘要及冻结名单，不重新读取收益面板计算。

```bash
factor-miner import-state-classification <完成的实验目录> <新的展示清单.json>
factor-miner publish-state-classification <展示清单.json> us_equity --dsn-env FM_DASHBOARD_DSN_US_EQUITY
```

每个状态记录保持原主张及区间性质。历史实验未声明最小经济幅度时保持该值为空并注明“本次未评价”，不能导入时补设门槛升级通过。

更新市场本地配置：

```json
{
  "regime_manifest_path": "/显式产物目录/展示清单.json",
  "regime_context_id": "从清单读取的context_id"
}
```

文件路径供主 Dashboard 使用，上下文供 PG 因子探索使用；两项必须引用同一发布。每个上下文内一候选至多一条当前记录，多个上下文不按更好的统计结果自动合并。新发布使用新清单路径，旧文件不覆盖。修正发布明确记录替代关系。

## 数据库与文件边界

新增 `factor_regime_hypotheses`、`factor_regime_validations` 及 `factor_regime_current`。稳定编号使用原映射；编号缺失或不符则回滚。导入幂等，既有基础因子表与原指标不改写。

```sql
SELECT factor_id, expected_regime_label, regime_validation_status,
       failure_condition_summary
FROM public.factor_regime_current
WHERE market_id = 'us_equity' AND context_id = '<显式上下文>'
ORDER BY factor_id;
```

核心筛选标签使用普通列，完整主张与检验报告保存为 JSONB，文件清单仍为正式来源。投影使用拥有目标表权限的现有数据库角色；连接身份错误应修正配置，不能靠重建数据库解决。PG 投影失败仅重试发布，不重跑研究。

无配置表示未登记；已配置但文件丢失、摘要不符、市场错误或身份错配，应显示明确错误。新假设与 Γ 的历史序列化不变，状态定义变化不会继承旧检验结论。
