# 记忆辅助假设生成与 120 槽运行手册

## 研究边界

这条流程只产生“通过冻结可见验证的候选因子”。记忆、gap 和模型输出用于安排研究，不证明因果机制，也不构成有效 Alpha、生产因子或投资建议。结果揭晓前必须冻结主张、机制、预期方向、可观察代理、独立验证、竞争解释、失效方式、证伪路径、评价政策和试验预算。

真实行情、标签、IC、回测和统计评价可在本地或服务器执行，但必须使用标准数据发布、独立产物目录和冻结研究身份。运行平台不改变证据等级。

## 固定顺序

1. 先查看指定 coverage graph 中 structural、market_regime、data_availability 三类 gap 摘要。`prepare-context` 只读取 cutoff 前已完成的正式 memory snapshot 和指定 graph，同一轮新写入的记忆不得进入上下文。
2. 用冻结 policy 运行 `evolution prepare-context`，显式指定正式 snapshot 和 gap report；命令会调用 verified graph loader，并核对 context、graph、memory、gap、字段注册表、评价政策和设计政策的 hash。不得用递归 glob 或任意 JSON 代替正式对象。
3. 由已授权的 hypothesis 角色生成正好 H01-H10。`generate-hypotheses` 只保存 request hash、response digest、provider/model identity 和脱敏 prompt bundle；原始模型响应不得进入 draft batch、Git、Dashboard 或外部日志。
4. 研究人员逐条检查十个 H 槽，再由 `approve-hypotheses` 写入人工决定。十条决定必须绑定同一个 context hash、family、草案 hash、审批角色和带时区时间；只有这个命令能把草案变成可执行批准批次。批准还必须携带并核验生成产物原样提供的 `request_sha256`、`report_sha256`、`gap_card_sha256`、`context_sha256`、`discovery_family_id`、十个 `draft_sha256` 以及 canonical `draft_batch_sha256`。这些字段不得从当前 context 或 decisions 补建。
5. 只有批准数正好为十，且 context、family、graph、memory 和批准批次 hash 一致，才允许进入表达式请求和回测。批准不足十个时不得创建 expression request、backtest 或 publication。

正式命令示例：

```text
factor-miner evolution prepare-context \
  --coverage-graph-root <verified-graph-root> \
  --memory-root <formal-research-memory-root> \
  --memory-snapshot-id <snapshot-id> \
  --gap-report <formal-gap-report.json> \
  --family-id <new-family> --policy <frozen-policy.json> --output <context.json>
```

`memory-root/index.json`、snapshot 内容 hash、snapshot 的 graph manifest hash、gap report 的 graph/memory hash 必须形成完整身份链；每条 snapshot entry 还必须在 cutoff 前创建、属于正式 family 白名单并能从正式账本复验。任一 hash 缺失、损坏、旧污染 family 或身份不一致都会非零退出，且不创建 output。

每个 H 槽固定生成三个设计。逐条核对 `field_set`、`operator_topology`、`temporal_role`、`input_combination`、`node_count`、`depth_range` 六个结构轴；三个设计不能只改变窗口或 period。检查应记录设计签名、AST hash 和输出相关性，并发生在 IC、标签和回测之前。随后才运行两个 LLM arm 和两个固定 shadow arm，形成 10 × 3 × 4 = 120 个槽。

## 状态解释

- `DESIGN_DIVERSITY_FAILED`：三个设计没有实质结构差异或违反冻结设计轴；槽保留终态，不进入表达式、IC 或回测。
- `cross_arm_redundant`：不同 arm 的规范 AST 或可见输出高度重复；不删除槽，只记录冗余关系。
- `not_executed`：未批准、无合格父候选或基础设施终止；仍占用原槽，不能借用别的假设补位。

## Seal、记忆与 Dashboard

120 个槽进入明确终态后运行 `campaign seal`，核对 seal 重算的槽对象、context、approval batch、gap report、graph、memory、design policy hash 和 120 槽预算。seal 前不得读取标签、IC、收益、冗余或 Barra 结果。发布后核对 memory snapshot 的 entry binding、来源 family、seal 和 cutoff；Dashboard 只显示脱敏摘要、批准数量、终态计数和身份 hash，数据库只是可重建只读投影。

## 纠正事件

失败或发现错误时保留原始草案、批准记录、槽对象和账本事件，不原地编辑、不删除、不以重试为理由重抽假设。纠正必须追加带 `supersedes_event_id` 的新事件；若影响 context、政策、family 或 seal，建立新的研究族重新走完整十槽批准流程。
