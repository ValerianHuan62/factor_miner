# 本地与服务器研究运行

## 结论边界

本地和服务器运行遵守同一研究协议。运行位置不会提升证据等级；只有数据身份、冻结切分、统计检验和独立验证完整时，结果才可称为“通过当前协议验证的候选因子”。

## 安装系统

```bash
uv sync --frozen
docker compose up -d postgres
export FM_DASHBOARD_DSN='postgresql://factor_miner:factor_miner_local@127.0.0.1:5432/factor_miner'
```

默认安装已包含 PostgreSQL 驱动、Plotly 和 Streamlit。已有 PostgreSQL 时可直接使用自己的 DSN，无需 Docker。

## 准备数据

```bash
uv run factor-miner data prepare-local <行情.csv或parquet> \
  --output-root <只读发布目录> \
  --artifact-root <独立产物目录> \
  --adjustment-convention <复权口径> \
  --calendar-version <交易日历版本>
```

输入已包含三类状态 mask 时无需额外选项；仅在明确确认所有记录均可用时使用 `--assume-tradable`。加载生成的 `runtime.env` 后运行 `factor-miner doctor` 检查身份和边界。

## 发布与展示

正式 Pilot 和 Campaign 发布命令要求 `--dsn` 或 `FM_DASHBOARD_DSN`，成功写入不可变产物后必须完成 PostgreSQL 投影。投影失败时保留事实源并返回失败，数据库恢复后使用对应 `project` 命令重试。

```bash
make dashboard
```

Dashboard 默认只读取 PostgreSQL 投影和已发布产物，不直接读取原始行情。服务器部署可使用 `deploy/` 下的 systemd 模板，本地运行不需要 SSH。
