# 本地与服务器研究运行

## 结论边界

当前使用现有 A 股研究代表时，先读[当前流程与日常使用](../当前流程与日常使用.md)。本手册说明安装、接入和运行方式，不表示需要重新挖掘、发布或覆盖已有本地配置。

本地和服务器运行遵守同一研究协议。运行位置不会提升证据等级；只有数据身份、冻结切分、统计检验和独立验证完整时，结果才可称为“通过当前协议验证的候选因子”。

## 安装系统

```bash
uv sync --frozen
docker compose up -d postgres
export FM_DASHBOARD_DSN_A_SHARE='postgresql://factor_miner:factor_miner_local@127.0.0.1:5432/factor_miner'
export FM_DASHBOARD_DSN_US_EQUITY='postgresql://factor_miner:factor_miner_local@127.0.0.1:5432/factor_miner_us'
```

默认安装已包含 PostgreSQL 驱动、Plotly 和 Streamlit。已有 PostgreSQL 时可直接使用自己的 DSN，无需 Docker。

## 准备数据

```bash
uv run factor-miner data prepare-local <行情.csv或parquet> \
  --output-root <只读发布目录> \
  --artifact-root <独立产物目录> \
  --adjustment-convention <复权口径> \
  --calendar-version <交易日历版本>
```

输入已包含三类状态 mask 时无需额外选项；仅在明确确认所有记录均可用时使用 `--assume-tradable`。加载生成的 `runtime.env` 后运行 `factor-miner doctor` 检查身份和边界。

## 发布与展示

正式 Pilot 和 Campaign 发布成功写入不可变产物后，必须投影到该市场自己的 PostgreSQL 数据库。A 股使用 `FM_DASHBOARD_DSN_A_SHARE`，美股使用 `FM_DASHBOARD_DSN_US_EQUITY`；禁止让美股回退到 A 股 DSN。投影失败时保留事实源并返回失败，数据库恢复后使用对应 `project --market-id` 命令重试。

```bash
make dashboard
```

Dashboard 默认打开“看结果”，提供“挖因子”“研究代表库”和“设置”入口；市场默认优先美股。日常使用 A 股代表库时，进入“研究代表库”并选择 A 股，可切换代表、替补和全部视图。代表角色来自 `joint_library_path`，原候选指标来自 `cost_review_path` 指向的文件发布；正式批次另有 PostgreSQL 查询路径，不能将全部页面描述为只读一个数据库视图。这些查询交互不会重算指标或改变候选状态。

跨市场模块使用被 Git 忽略的本地配置：

```bash
cp -n configs/market-profiles.example.json configs/market_profiles.local.json
make dashboard
```

每个市场必须配置显式行情表、状态表、字段映射、复权口径、交易日历、独立产物根和独立 PostgreSQL 数据库。侧栏切换的是两套同构系统，不是把两种数据放进同一目录。没有已发布运行时，页面仍可打开，但不会伪造图表或指标。完成正式运行后，页面自动寻找该市场最新投影；也可分别用 `FM_DASHBOARD_RUN_ID_A_SHARE` 和 `FM_DASHBOARD_RUN_ID_US_EQUITY` 选择已发布运行。

真实单因子回测使用市场配置中的可选 `backtest_path`。该路径必须指向由 `dashboard.build_real_backtest` 生成的聚合 JSON，Dashboard 只读取逐期收益、换手、成本、基准和审计元数据，不读取或暴露个股持仓。美股当前协议使用 `security_id`、拆分复权开盘价、显式可交易状态、信号日后下一交易日开盘建仓，并在冻结持有期后的开盘退出。若仅使用开发区间，产物和页面必须标记为 Smoke，不得称为冻结 OOS 证据。

```bash
uv run python -m dashboard.build_real_backtest \
  --factor <raw_factor.parquet> \
  --market <market.parquet> \
  --state <state.parquet> \
  --manifest <manifest.json> \
  --output <独立产物目录/回测.json> \
  --source-candidate-id <内容寻址候选ID> \
  --factor-id <Dashboard编号> \
  --factor-name <因子名称> \
  --start <开始日期> \
  --end <结束日期> \
  --rank-ic-mean <开发期RankIC> \
  --rank-ic-hac-t <开发期HAC-t>
```

`FM_ARTIFACT_ROOT` 与 `FM_DASHBOARD_ARTIFACT_ROOT` 仅作为旧部署或临时调试的可选覆盖，不是 Dashboard 启动前提。服务器部署可使用 `deploy/` 下的 systemd 模板；Mac 本地运行不需要 SSH，也不要求 Linux。
