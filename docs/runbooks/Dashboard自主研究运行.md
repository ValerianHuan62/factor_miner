# Dashboard 自主研究运行手册

## 研究边界

运行台产生的是“通过可信可见验证的候选因子”，不是认证 Alpha、生产因子或实盘建议。假设中的机制在独立检验完成前始终标记为尚未验证；相关性不能证明因果，开发区间通过也不能代表未来有效。

每批评价在结果揭晓前冻结股票池、标签、时点、统计方法和候选族规模。因子在当日收盘后观察，最早于下一交易日开盘使用。分钟数据只以事先聚合且满足可得性合同的日级字段进入候选，不允许盘中未来信息。

## 新建研究批次

1. 打开侧栏中的“研究运行台”。
2. 确认顶部 Worker 状态为“在线”。
3. 在没有活动批次时点击“新建研究批次”。
4. 页面显示命令已进入队列后等待状态变为“等待审批”。不要重复刷新按钮；相同操作会按内容身份幂等处理。

新建批次只授权本批的假设和表达式两个模型角色。假设生成一次，表达式在全部审批冻结后批量生成一次。页面不展示调用计量，也不读取模型原始响应。

## 审批十条假设

运行台固定为三栏：左侧是 H01–H10 目录，中间是完整正文，右侧是审批与时点信息。

逐条阅读以下九类内容，页面不会截断：

- 主张
- 机制
- 预期方向
- 可观察代理
- 独立验证
- 竞争解释
- 失效方式
- 证伪路径
- 来源与边界

每条必须选择“批准此假设”或“拒绝此假设”。拒绝项不会补位，也不会从记忆中删除。十条决定未齐时，系统不会调用表达式模型或读取候选结果。

## 冻结并运行

审批进度达到 10/10 后点击“冻结十条审批并继续”。批准数量乘以三就是本批不可修改的候选检验族规模。例如批准七条时固定二十一个槽。

表达式 Schema 校验、未来信息检查或计算失败的槽仍保留在原统计族中，不会补候选。Worker 随后依次执行：

1. 生成表达式
2. 登记候选清单
3. 真实数据计算与评价
4. 发布不可变产物
5. 投影 PostgreSQL 中文读模型
6. 刷新下一轮记忆与因子图谱
7. 完成运行

只有 IC、RankIC、波动、IR、HAC t 值、胜率、年化收益、最大回撤、Sharpe 和 information ratio 全部存在的已评价候选，才允许进入 PostgreSQL 完整候选视图。胜率使用冻结组合口径的逐期 `Q10_Q1_net_return` 计算。

## 查看状态与恢复

顶部显示 Worker 在线状态、批次编号、中文阶段、审批进度和最近错误。浏览器或 Dashboard 重启不会重复模型调用；Worker 根据不可变阶段对象恢复。

若阶段显示“运行失败”，先阅读中文错误，再点击“从当前阶段继续”。继续命令绑定当前失败状态，已经完成的模型调用、评价、发布和投影不会重做。若相同错误反复出现，应停止点击并联系维护者核对服务器输入、数据库或外部模型服务。

## 记忆与因子图谱

本批十条假设的批准或拒绝状态，以及冻结候选族中评价成功、失败和未执行状态，都会进入下一轮轻量记忆。具有真实 typed AST 的候选进入轻量因子图谱目录；分钟聚合字段带有 `intraday_aggregate` 标签。

新记忆、新图谱和缺口简报只供下一批使用，不会回灌当前批的假设或表达式请求。旧正式 120 槽记忆、generation seal 和覆盖图谱合同保持不变。

## 何时联系维护者

出现以下情况时不要尝试修改数据库或产物文件：

- Worker 长时间离线且服务重启后仍未恢复
- 状态提示数据发布、字段注册表、状态表或清单哈希不一致
- PostgreSQL 投影拒绝核心指标为空
- 同一状态 sequence 或内容哈希冲突
- 运行目录、JSONL 账本或不可变对象损坏
- DeepSeek 录制身份或当前请求身份不一致

PostgreSQL 是可重建读模型，JSON、JSONL 和正式运行产物才是状态真相。不要在数据库中手工补零、改写 `huanNNN`、删除失败槽或覆盖事前假设。
