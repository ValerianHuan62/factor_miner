# 因子宽表导出与模型接入

已采纳的研究代表可以交给下游模型项目作为原始特征输入。导出保留原统计资格、经济机制状态和历史选择区间，不把代表库采纳视为正式统计确认，也不把原始宽表视为已完成的模型 Dataset。

## 导出入口

先按[代表库采纳合同](../contracts/联合诊断代表库采纳.md)完成审核与采纳，再指定代表库和下游输出文件：

```bash
uv run --frozen factor-miner export-joint-features \
  /path/to/adopted-library \
  /path/to/downstream/feature/factor_miner_raw_factors_VERSION.parquet
```

`export-joint-features` 只导出角色为“研究代表”的成员，数量由库决定，不硬编码为 36。它校验采纳库、诊断快照、原始矩阵和 Spec 身份；源数据变化、重复键、无穷值、缺失计算资格或已有目标文件均失败。按年合并并回读验证后，发布单个 Snappy Parquet 和同名 `.manifest.json`。下游应同时保留两者，并核对清单中的 Parquet SHA-256。

未来审核后的代表库可以继续使用这一入口，指定新版本文件名并写入同一下游特征目录。每次发布是完整成员快照；不要将多个快照横向拼接成重复因子，也不要直接覆盖旧发布。

## 宽表合同

| 项目 | 约定 |
| --- | --- |
| 唯一键 | `date`、`order_book_id`，按日期和证券排序 |
| 因子列 | `factor_miner_huanNNN`，与清单内稳定编号一一对应 |
| 数值 | 原始公式值，不按预测方向翻转、不标准化、不填零 |
| 缺失 | 计算无效或 NaN 转为 null，保留日期证券键并集 |
| 来源 | 清单保存 `producer=factor_miner`、Spec 与源矩阵身份、候选资格、原方向和成员角色 |
| 数据身份 | 清单保存 release、复权、日期范围、行数、证券数与各年缺失统计 |
| 时间语义 | 当前出口为收盘后可得的日频因子，最早下一交易时段执行；不含收益标签 |

本出口面向当前日频原始矩阵合同。其计算资格随每列空值体现，排名和交易资格由下游显式连接同版本状态表，不能由宽表非空值推断。

## 接入模型前

对齐行情、状态、复权与交易日历，冻结模型使用的列清单、股票池和预处理，再构建标签与 Dataset。标准化和缺失处理属于下游协议；训练和验证按标签事件区间做 purge。来源清单记录已参与因子筛选的历史区间，这些日期不能作为全新密封测试集。

本机已约定使用 `huan_quant/pipeline/feature/` 接收 Factor Miner 发布。具体版本、实际覆盖日期和训练准备状态写在该目录的 `README.md`。核心包不 import 下游项目；导出不会触发新因子挖掘、标签生成或模型训练。

## 文件管理

代码、出口合同和合成测试进入 Git；真实宽表与含私有路径、候选详情的来源清单保存在下游本地产物目录并加入 Git 忽略。Factor Miner 原始矩阵和账本保持只读，宽表交付不授予清理来源的权限。
