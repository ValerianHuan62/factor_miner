# 正式研究族 120 槽服务器运行手册

## 研究边界

本手册用于阶段 C 的正式研究族治理。运行结果只能称为“通过冻结可见协议计算的候选因子
诊断”，不能称为有效 Alpha、认证因子、因果机制成立或生产结论。所有假设、字段可用性、
评价关系、HAC 参数、Bonferroni 分母和失败处理规则必须在读取任何结果前冻结。

真实候选计算、IC、组合和 Barra 只在公司 Linux 服务器执行；Mac 只做合成测试、代码审查
和 SSH 远程操作。`/data/quantlake` 只读，产物写入独立的阶段 C 产物根目录。旧的
`llmfamily_1bae19965638a6ac9620e0b0` 属于污染族，禁止读取其内容参与新研究、追加事件、
覆盖对象或删除文件。

## 运行前检查

服务器必须具备：

- 新建且唯一的 `family_id`，不能使用污染族或阶段 A、阶段 B 的 Pilot 身份；
- 最多两条 LLM arm、每条最多 10 个经人工批准的假设，以及每个批准假设的不可变内容哈希；
- 公司外发政策、字段可用性注册表、脱敏 payload、请求授权和评价配置；
- QuantLake release、状态表、交易日历、评价区间和代码提交身份；
- 显式独立的阶段 C 产物根目录和单写入器锁。

缺少批准假设、授权、字段注册表、数据版本、状态表或评价器时必须停止；不能用空值、
静默补缺、临时批准或旧族记录代替。

## 固定执行顺序

先完成人工批准和请求授权，再运行四条 arm 的生成流程。中断后继续同一命令或使用正式
恢复流程，只恢复已有不可变对象，不生成新的研究想法。

```bash
factor-miner campaign run-approved <new_family_id> \
  <approved_hypotheses.json> <policy.json> <payloads.json> \
  <field_registry.json> <authorizations.json> \
  --artifact-root <stage_c_artifact_root>
```

该命令只负责生成治理和槽位终态。批准候选完成后，固定程序运行两个确定性 shadow arm，
并将未批准或无法执行的槽写入明确终态。四条 arm 的 120 个槽全部终结后才允许封存：

```bash
factor-miner campaign seal <new_family_id> <seal_input.json> \
  --artifact-root <stage_c_artifact_root>
```

封存成功后，先核验 seal 和对象哈希，再调用服务器统一 Pilot 评价器。评价器应输出按
`slot_id` 索引的 120 条记录，并保留成功、失败、重复和未执行槽；任何槽缺失都应停止：

```bash
factor-miner campaign evaluate <new_family_id> <evaluation_results.json> \
  --artifact-root <stage_c_artifact_root> --dsn <dashboard_dsn>
```

最后执行只读审计：

```bash
factor-miner campaign verify <new_family_id> \
  --artifact-root <stage_c_artifact_root>
```

## 验收与留档

验收至少包括：事件链连续且单写入器；120 个槽均为不可变终态；seal 重算哈希一致；评价
结果保留完整 120 槽分母；HAC 参数和 Bonferroni 分母来自冻结政策；规范 AST 和逐日输出
相关性检查均有记录；发布清单逐文件核验；Dashboard 只能从已发布产物投影；数据库删除后
可以从 JSON/JSONL 重新投影。

缺少真实 Barra 输入时只能记录 `not_available` 或合同规定的明确状态，不能伪造归因。任何
统计通过也不改变候选因子诊断的研究边界，不得自动导入生产系统。

## 当前服务器前置条件

阶段 C 代码和隔离运行目录可以进行合成治理测试；正式 120 槽研究仍需服务器提供完整的
事前批准假设集合。若批准数量不足 10 个，程序可以保留未执行终态用于治理演练，但不能把
该演练称为正式 120 槽研究结果，也不能把旧污染族当作补充输入。
