# 候选筛选与稳健性报告运行手册

本文保留旧版产物筛选与固定单因子协议的复现说明，其中门槛不自动适用于已采纳的 A 股研究代表库。当前日常入口见[当前流程与日常使用](../当前流程与日常使用.md)，成员规则见[联合诊断代表库采纳](../contracts/联合诊断代表库采纳.md)。

## 研究边界

本流程停止生成新候选，只对截止时点前已经取得稳定 `huanNNN` 编号的候选全集进行筛选。输出只能称为“通过当前协议筛选的候选因子”，不能称为认证 Alpha、生产结论或实盘建议。

筛选不会用 PostgreSQL 替代正式产物。稳定编号存在但无法回到不可变候选 Spec、确认期 IC、组合逐期收益或发布清单的记录，必须列为“输入不可审计”，不得用数据库中的最近期数字补齐。

## 冻结规则

旧版产物级复核先执行 `freeze-policy`，再读取逐候选结果。v2 保留用于复核历史报告：

- 发现期决定方向，确认期不得重新选择符号；
- 确认期方向校正 RankIC 不低于 `0.01`，且原冻结 HAC/Bonferroni 状态通过；
- 确认期年度 RankIC 至少三分之二方向为正；
- 1、3、5、10、20 日期限至少五分之三方向为正；
- 确认期净 Sharpe 和相对沪深300的信息比率均为正；
- 最近期方向校正 RankIC 和信息比率均为正；
- 28bp 成本压力下信息比率为正，42bp 成本压力下净 Sharpe 为正；
- 用已发布的逐期高值组减低值组净收益进行相关去重，绝对相关阈值为 `0.80`；
- Barra 和市场状态只作并列诊断，不改变主筛选状态。

v1 使用目标多头主动收益去重，容易把共同市场和风格成分误判为因子信号重复，只保留作历史诊断。v2 使用冻结极端组差净收益序列，但不是新的固定候选核心池协议。新正式筛选以 `skills/factor-screening-protocol/SKILL.md` 为准：明确报告 IC mean 与 RankIC，先做 HAC/Bonferroni 和确认期硬门槛，再按逐日截面因子值去重，最后用 `rolling_ridge_v1` 检查组合增量。

## 服务器运行

先从内部稳定编号表导出不含指标的映射 CSV，再冻结政策：

```bash
factor-miner screening freeze-policy \
  --cutoff-at 2026-08-26T06:08:40Z \
  --target-min 20 \
  --target-max 30 \
  --policy-version candidate-screening-v2 \
  --output <筛选政策路径>
```

随后执行报告：

```bash
factor-miner screening build \
  --artifact-root <正式产物根目录> \
  --candidate-map <稳定编号映射CSV> \
  --policy <筛选政策路径> \
  --output-root <独立报告根目录> \
  --regime-snapshot-root <可选已核验市场状态快照>
```

报告目录按内容寻址，包含：

- `policy.json`：冻结政策；
- `report.json`：完整机器可读判定；
- `候选筛选与稳健性报告.md`：中文主报告；
- `候选明细.csv`：全部可审计候选及淘汰原因；
- `输入不可审计候选.csv`：稳定编号存在但缺少完整正式产物的候选；
- `manifest.json`：逐文件 SHA-256、大小和报告身份。

## 开盘价标签与简单 Ridge

旧策略面板若仍包含 VWAP 标签，只保留特征列并重建标签：

```bash
factor-miner screening rebuild-open-panel \
  --feature-panel <周频特征面板> \
  --market <行情分区1.parquet> \
  --market <行情分区2.parquet> \
  --state <显式状态表.parquet> \
  --output <新的open标签周频面板.parquet>
```

默认字段适配 QuantLake 的 `date/code/adj_open` 与 `trade_date/code/valid_for_trading`，也可通过列名参数适配其他显式 Parquet 发布。标签使用全市场交易日历固定的未来第 1 与第 6 个交易日复权开盘价；个股在任一固定日期不可执行时保持缺失，不得通过删除停牌日把持有期向后延长。

相关去重后的候选清单可直接运行标准 Ridge：

```bash
factor-miner screening rolling-ridge \
  --panel <新的open标签周频面板.parquet> \
  --candidate-list <含business_id的候选CSV> \
  --evaluation-start 2021-01-01 \
  --evaluation-end 2026-06-30 \
  --output-root <新的独立Ridge产物目录>
```

基本面基准可改用 `--feature-prefix fin_`；基本面加候选则同时提供 `--feature-prefix fin_` 和 `--candidate-list`。三个模型使用相同的 156 周训练窗、26 周内层验证、1 周标签结算隔离、4 周重训、alpha 网格、Top50、开盘价标签和成本。内层验证以逐周截面 Spearman 均值选 alpha；确认区间已经被读取后只能称为诊断，不是新的密封 OOS。

## QuantLake 截面因子批量筛选

`cross_section_factor` 已完成上游截面预处理，不得再次缩尾或标准化。先将年度宽表分区转换为周频 `mean5/last` 面板；缺少可信事前方向的历史因子只在发现期按 RankIC 均值确定一次方向：

```bash
factor-miner screening build-quantlake-panel \
  --factor <cross_section_factor年度分区1.parquet> \
  --factor <cross_section_factor年度分区2.parquet> \
  --label-panel <既有open-to-open标签面板.parquet> \
  --output-root <新的QuantLake筛选面板目录> \
  --batch-size 30
```

每批都必须使用完整冻结因子族数量作为 Bonferroni 分母：

```bash
factor-miner screening screen-single-factors \
  --panel <weekly_factor_features_001_open.parquet> \
  --candidate-list <candidates_001.csv> \
  --output-root <single_fixed_001> \
  --family-size <完整冻结因子数>
```

有效周数不足的因子记为 D 级拒绝并保留在检验族中，不得导致整批中止。合并分批结果时同样显式传入 `--family-size`。只有硬门槛通过候选才使用 `build-quantlake-selected-daily` 构建发现期日频面板，再运行 `cluster-fixed`；这可避免为已淘汰因子生成大体积聚类数据。

## 结果解释

“统计候选”表示通过数据、发现期统计和冻结方向确认期门槛，可进入相关性去重与模型增量研究。单因子 Sharpe、换手、利润集中度、成本压力和分组单调性在这一层作为经济警告与排序信息，不再删除统计候选。“核心候选”必须进一步通过相关性、模型增量和最终组合经济门槛。“未入选”必须保留具体失败原因。

市场状态覆盖不足确认期八成时，只显示描述性结果，不宣称跨状态稳健。Barra 共同因子贡献高或主动暴露大也不自动淘汰；后续组合阶段应并排比较原组合与行业、Size、Liquidity、Volatility 等中性组合。

## 后续策略阶段

先对核心候选构建透明的等权标准化组合，再加入观察候选做边际贡献比较。固定组合收益形成后再运行 CPCV 和 Deflated Sharpe Ratio；试验数量必须考虑完整候选筛选过程，不能只填最终入选数量。报告截止时点之后的数据才可作为新的纸面样本外跟踪。
