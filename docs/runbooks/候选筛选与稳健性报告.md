# 候选筛选与稳健性报告运行手册

## 研究边界

本流程停止生成新候选，只对截止时点前已经取得稳定 `huanNNN` 编号的候选全集进行筛选。输出只能称为“通过当前协议筛选的候选因子”，不能称为认证 Alpha、生产结论或实盘建议。

筛选不会用 PostgreSQL 替代正式产物。稳定编号存在但无法回到不可变候选 Spec、确认期 IC、组合逐期收益或发布清单的记录，必须列为“输入不可审计”，不得用数据库中的最近期数字补齐。

## 冻结规则

正式运行先执行 `freeze-policy`，再读取逐候选结果。当前 v2 政策固定使用：

- 发现期决定方向，确认期不得重新选择符号；
- 确认期方向校正 RankIC 不低于 `0.01`，且原冻结 HAC/Bonferroni 状态通过；
- 确认期年度 RankIC 至少三分之二方向为正；
- 1、3、5、10、20 日期限至少五分之三方向为正；
- 确认期净 Sharpe 和相对沪深300的信息比率均为正；
- 最近期方向校正 RankIC 和信息比率均为正；
- 28bp 成本压力下信息比率为正，42bp 成本压力下净 Sharpe 为正；
- 用已发布的逐期高值组减低值组净收益进行相关去重，绝对相关阈值为 `0.80`；
- Barra 和市场状态只作并列诊断，不改变主筛选状态。

v1 使用目标多头主动收益去重，容易把共同市场和风格成分误判为因子信号重复，只保留作历史诊断。正式筛选使用 v2 的冻结极端组差净收益序列。

## 服务器运行

先从内部稳定编号表导出不含指标的映射 CSV，再冻结政策：

```bash
factor-miner screening freeze-policy \
  --cutoff-at 2026-08-26T06:08:40Z \
  --target-min 20 \
  --target-max 30 \
  --policy-version candidate-screening-v2 \
  --output <筛选政策路径>
```

随后执行报告：

```bash
factor-miner screening build \
  --artifact-root <正式产物根目录> \
  --candidate-map <稳定编号映射CSV> \
  --policy <筛选政策路径> \
  --output-root <独立报告根目录> \
  --regime-snapshot-root <可选已核验市场状态快照>
```

报告目录按内容寻址，包含：

- `policy.json`：冻结政策；
- `report.json`：完整机器可读判定；
- `候选筛选与稳健性报告.md`：中文主报告；
- `候选明细.csv`：全部可审计候选及淘汰原因；
- `输入不可审计候选.csv`：稳定编号存在但缺少完整正式产物的候选；
- `manifest.json`：逐文件 SHA-256、大小和报告身份。

## 结果解释

“核心候选”表示通过全部硬门槛且是相关簇内排序最高的代表。“观察候选”表示通过硬门槛，但为了达到研究池下限保留的簇内次优候选；它不能与核心代表视为独立 Alpha。“相关簇备选”通过硬门槛但未进入最终研究池。“未入选”必须保留具体失败原因。

市场状态覆盖不足确认期八成时，只显示描述性结果，不宣称跨状态稳健。Barra 共同因子贡献高或主动暴露大也不自动淘汰；后续组合阶段应并排比较原组合与行业、Size、Liquidity、Volatility 等中性组合。

## 后续策略阶段

先对核心候选构建透明的等权标准化组合，再加入观察候选做边际贡献比较。固定组合收益形成后再运行 CPCV 和 Deflated Sharpe Ratio；试验数量必须考虑完整候选筛选过程，不能只填最终入选数量。报告截止时点之后的数据才可作为新的纸面样本外跟踪。
