# 美股全库统一复核

## 研究目的

“正式批次”只代表登记与执行来源，不是因子质量认证。全库复核必须覆盖所有唯一编号，包括试运行、历史正式和近期新增候选；不能把不同采样频率、不同多重检验家族的结果直接拼接排名。

## 固定顺序

1. 从原始不可变 Spec 核对业务编号、原公式、原主张与预期方向，冻结完整试验族。重复公式仍计入全部名额。
2. 对全部公式重新做类型与时点校验、股份单位不变性、金融状态响应反例。补做的观察条件属于事后审计，不得改写为事前经济证据。
3. 通过 `run-research-report` CLI，按同一数据版本、同一日历、同一标签、同一采样频率重新计算发现、确认与因果持仓报告。
4. 原假设复核使用 `direction_policy=original_hypothesis`。发现期反号必须暴露，不得自动翻转为表现更好的策略。过去使用发现方向冻结的运行保持原有历史身份。
5. 对构念与发现期统计合格者，再核对语义；发现期逐日截面绝对 Spearman 的95分位用于全库去重。按发现期绝对 HAC t 冻结代表，不用确认收益挑代表。
6. 固定发现期最强代表作为增量对照，其余低相关代表逐个加入。模型名单绑定原报告哈希，通过 `run-incremental-report` 执行；使用全库名额校正，预测截面不由未来标签资格决定。
7. 统一列出全部因子的处理理由。研究基底、同类替补、待补证候选与不通过者分别展示；原账本不删除。

## 经济解释边界

原公式、原叙事、原文献的支持范围要逐项对应。高低价估计方差的论文不自动证明低振幅收益溢价；异常放量后的正向收益文献不能直接支持量冲击反转。无法对应的叙事先留作待补证，不按漂亮 IC 补写故事。

每个候选披露统一成本下的最后报价参考估值、零回收压力和分年度稳定性。条件预测增量不是实际投资表现；未确定最终回收价值时，正式实际收益仍不能用情景值替代。事后全库复核不产生新的密封样本外区间。

## 可重复执行

```bash
PYTHONPATH=src:. .venv/bin/factor-miner run-research-report <冻结全库配置>
PYTHONPATH=src:. .venv/bin/factor-miner run-incremental-report <绑定名单后的增量配置>
PYTHONPATH=src:. .venv/bin/python -m unittest tests.test_research_report_contract tests.test_research_incremental tests.test_library_review -q
```

运行配置、真实产物与名单放在显式的独立产物目录，不进 Git。输入发布保持只读；任何修改后的代码都必须有与实际执行一致的代码快照或独立增量代码身份。
