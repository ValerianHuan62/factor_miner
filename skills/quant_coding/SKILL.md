# Factor Miner 量化开发规范

## 语言规则

- 对用户的回复、代码注释和文档字符串使用中文。
- Markdown 文档的标题与正文使用中文；代码标识、命令、路径、标准缩写和专有名词可以保留原文。
- 先解释金融研究问题、假设和风险，再解释程序如何实现。

## 金融研究规则

- 明确因子的金融含义、预期方向、观察时点、最早交易时点和失效条件。
- 严禁未来函数、标签泄漏、期末成分股回填和使用未来状态。
- 固定持有期标签按统一市场交易日历连接固定入场/退出日；证券缺行产生结构性 null，不得用分组 `shift` 偷换事件日期。
- 训练、验证、确认和测试的边界必须按标签退出事件 purge；信号日落在训练集不代表标签事件属于训练集。
- 回测必须先用信号日信息冻结选择。未来买不到只能留现金，未来卖不掉只能锁仓并逐日重试，不能先过滤未来可成交证券再排名。
- 区分原始因子、预处理、评价标签和回测；不得把这些步骤混成一个不可审计过程。
- 评价因子时说明股票池、标签、覆盖率、RankIC、显著性方法和多重检验范围。
- 未完成独立机制检验和密封样本外检验时，结论只能称为“通过当前协议验证的候选因子”。

## Python 与数据规则

- 真实研究可在本地或服务器运行；SSH、Linux、QuantLake 和个人数据库都不是核心运行前提。
- A 股、美股及其他市场统一通过标准面板合同接入；市场特有的交易状态必须由适配层显式映射为三类 mask。
- QuantLake 只是一种可选 A 股数据来源，输入发布与运行产物必须分离并绑定清单、哈希、截止日、复权和日历身份。

- 优先使用清晰、可测试的函数和显式类型，避免隐藏状态和静默兜底。
- 表格计算优先采用 Polars 表达式和向量化操作，避免无必要的逐行循环。
- 时间序列和截面计算必须明确排序键、分组键、空值语义和最小样本要求。
- 输入、输出、版本、哈希和失败原因必须可审计；真实数据、运行配置、账本和产物不得进入 Git。
- 任何受支持平台都可运行真实研究，但必须使用显式发布、不可变身份和独立产物目录；平台本身不能替代数据治理。

## 筛选后归档与大文件清理

采用“清理可重建大矩阵，保留研究痕迹”的方式管理已完成筛选的候选。适用于本项目各市场；候选归档不等于永久无效，不改变原有筛选结论。

- **清理范围**：按当前任务已授权的市场、批次和候选清单执行，不重复索要已有授权，也不把本规则视为扫描并删除全部历史产物的授权。默认只清理本轮明确未保留候选的 `raw_factor.parquet`；保留基底、观察池和同类替补的矩阵继续保留。其他大文件须单独核对用途与授权范围。
- **清理前核对**：确认研究已结束、没有运行任务使用目标文件，目标不属于继续研究的基底、增量模型或其他有效任务的输入。验证候选身份、筛选报告、账本与冻结配置一致；确认原数据版本、公式和代码可用于重算。任一依赖不清楚时，保留该文件并明确原因，不按文件大小猜测。
- **永久保留研究痕迹**：保留 CandidateSpec、CampaignSpec、稳定业务编号与候选身份映射、全部试验事件、原假设及方向、构念检验、冻结协议与预算、代码快照、数据版本引用、IC 序列及 HAC/多重检验结果、相关性与增量检验结果、成交记录、筛选理由和 Dashboard 报告。不得整目录删除候选，或用一份简短摘要替代原始统计记录。
- **先登记、后清理、再核验**：独立保存清理清单，记录候选编号、路径、大小、文件哈希、淘汰原因及来源运行身份；预检全部目标后逐文件删除。不得修改原 CandidateSpec、CampaignSpec、账本或研究报告。完成后保存回执，核验保留文件内容未变、账本完整、报告可读，并报告实际删除数量与文件字节数。中断或部分失败须如实记录，不能宣称全部完成。
- **多重检验名额不消失**：失败、重复、中断和被归档的候选仍属于其原先冻结的检验族。不得按磁盘剩余文件数或在研候选数重算 Bonferroni 分母；后续批次使用事前冻结的预算与检验族，不能借删除文件或另建批次重置已发生的适应性试验历史。
- **日常使用**：Dashboard 默认展示保留基底、观察池和同类替补，未保留候选放入“淘汰档案”，“全部”仍可查阅完整记录。后续计算只加载显式选中的研究输入，不为日常展示重复计算已淘汰矩阵；去重与试验登记仍查询完整历史。
- **重算边界**：清理回执须明确哪些矩阵已不存在，以及重算所需的原数据版本、配置和代码。不得声称清理后的运行仍保存全部计算矩阵，也不得自动用最新数据覆盖原结果。

执行归档或修改相关读模型时，读取[既有因子复核读模型合同](../../docs/contracts/既有因子复核读模型.md)。上述规则由代理执行，不得让核心包或 CLI 在运行时依赖本 Skill。

## 输出方式

- 用业务语言先说结论，再给必要的技术细节。
- 修改代码时说明其对应的金融不变量，例如“结果揭晓前冻结规则”或“信号后下一交易日才能成交”。
- 不夸大统计结果；相关性不等于因果机制，开发区间通过不等于可以实盘。

## 跨市场新假设研究入口

- 2026年9月10日起，A 股与美股新增信号探索默认使用[跨市场探索入口与确认分层](../../docs/contracts/跨市场探索入口与确认分层.md)的 `favor-exploration-v1`。按连续、离散状态、事件类型冻结测量，再生成公式；探索资格不强制五组、三档联合或边际 IC 显著，正式通过标准保持。下列五分位与联合要求适用于显式登记的 FaVOR 联合确认路径，不能套用为所有探索的准入要求。

- 新增 A 股和美股假设研究使用[跨市场假设约束与 FaVOR 联合研究](../../docs/contracts/跨市场假设约束与FaVOR联合研究.md)。先用 `register-favor` 冻结假设、观察条件、Γ、分区、数据发布和有限预算，再接收公式；不得从生成好的公式反推并补写本次 Γ。
- DeepSeek API 和 GPT‑6 使用同一 `favor-request` / `submit-favor` 合同。生成模型不能批准自己绕过 Γ、合成反例或真实构念检查。
- 使用 `run-favor` 执行五分位构念验证、多条件 AND、q50/q70/q90 三档方向选择性和验证期阈值选择；不能用平均排名或 Ridge 替换本次授权的 FaVOR 联合策略。
- 窗口和参数变体占预留槽，失败和重复保留记录。不得用不同目录或生成方式重置已消费预算。
- 通过联合筛选的组成资格与单因子统计显著性分别记录。`publish-favor` 只把保留组成和组合写入完整投影，其余只入试验索引。旧因子需要新版本复核，不能自动升级。
