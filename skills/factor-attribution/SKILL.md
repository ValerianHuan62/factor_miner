# 因子收益归因与策略诊断

## 研究目标

回答四个问题：收益来自哪里；组合如何利用现有信号；交易后还剩多少收益；哪些结论有新的独立验证。把经济机制、预测信息、风险暴露和实际交易价值分开评价。判断是否存在 pure alpha 时，给出控制范围、剩余效果及未排除的解释，不把回归残差自动命名为独立 Alpha。

先遵守 [quant_coding](../quant_coding/SKILL.md)。本 Skill 负责研究决策与执行顺序，真实计算走项目 CLI，不能把因子计算或回测实现搬进 Skill。用户仅要求审阅已有结果时，读取产物即可；要求执行归因时，推进已授权的计算，不另设重复审批。

默认按以下四步执行。局部请求只执行有关部分；缺少某类归因数据时继续可独立完成的工作，明确该缺口限制了哪个结论。历史实例参数见[执行入口与产物核验](references/执行入口与产物核验.md)，不能当成所有市场和因子数量的通用参数。

## 开始前：绑定研究对象与冻结比较

1. 找到用户指向的不可变研究产物，核对因子业务编号、CandidateSpec、原假设方向、股票池、预测版本、训练窗口、标签事件、成交时钟与估值情景。PostgreSQL 和 Dashboard 只用于定位，不替代原始记录。
2. 先查真实数据结构、日期覆盖、证券身份和发布版本。逐年核对行业有效期、市值或股本、流动性、风险因子收益等字段，不能凭“有 CRSP”“有行情”推断全年数据齐备。区分历史有效日期和已证明的信息可得日期。
3. 在读取本轮新增比较结果前，冻结模型、方向、分组边界、控制变量、共同截面、成本、持有期、HAC 参数和有限检验预算；继承已有试验历史。既有结果已被查看须标记消费状态，不能通过新登记恢复为密封样本外。
4. 保存配置、全部实际依赖的输入哈希、代码版本与快照、数据身份和登记时间。使用新的输出目录；失败保留记录，修正后以新版本重试，不覆盖旧协议、试验或结果。

## 第一步：归因收益来源与剩余信号

### 先对账，再解释

- 解释已有策略时，先复现原基线。使用原始共同股票池；扩大到仅要求目标因子完整的股票池属于另一项研究，不能混入基线比较。
- 按每笔持仓计算：净损益 = 期末市值 − 期初市值 + 卖出及终止回收 − 买入 − 交易成本。持仓、现金及其他实际现金流都必须纳入适用的账本；当前实例没有额外现金收益，不向其他引擎机械套用。
- 逐日对账净损益之和与净值变化，再按损益发生年份和信号日冻结的行业、市值、流动性归因。未知类别独立保留。
- 年度组别贡献 = 年内该组净损益之和 / 年初净值。每个维度分别加总到当年区间收益；行业、市值和流动性是同一收益的不同分类，不能互相相加。
- 同时报告收益贡献与持仓暴露，注明暴露的加权方式、现金是否包含。半年收益不能称为全年收益；数年的年化指标不能代替逐年检查。

### 检查暴露与条件效果

- 行业用信号时点适用的历史分类，市值核验单位及股本可得时点。某年缺失时不能把上年股本或今天的行业回填进去，也不能用价格、成交额冒充市值。
- 从基础数据计算控制变量时，使用信号日及以前的固定市场日历窗口；缺行、停牌及无效价格遵循冻结规则，不把证券自己的若干行误当成连续交易日。
- 在**相同完整样本**上比较控制前后效果。当前条件 RankIC 方法分别将信号秩和未来收益秩对行业虚拟变量及连续风格秩回归，再计算残差相关性；同期回归用于解释，不能把未来收益拟合成历史预测。
- 同时保存有效证券数、逐年覆盖、原始相关性、剩余相关性、HAC t 和校正 p。行业与量价控制不等于完整 Barra/Fama-French；未包含的市场 beta、价值、盈利、投资等暴露须明确列出。
- 若使用外部风险因子回报，核对市场、币种、收益时钟、价格或总收益、无风险收益及可得区间。开盘到开盘与收盘到收盘数据不能直接冒充严格对齐的收益归因。
- 相关性衰减不是收益被解释的百分比；显著残差不是机制证明。某个因子出现剩余信号后，继续查看扣费交易结果，不能结果后改方向或直接挑出上线。

## 第二步：比较组合方式，区分选股与避雷

- 在同一信号日、同一可排名股票池、同一标签与成交规则下，比较现有模型和一个事前冻结的简单基线，例如按原方向等权的因子排名。方向与权重来源必须可追溯。
- 需要重训时按标签退出事件 purge，记录每次拟合可见数据和参数；已有冻结预测可直接复用。不要因看到结果而搜索因子子集、权重或模型参数。
- 检查逐年 IC、RankIC、十分组或冻结分组的收益形状，以及顶部、底部和中间组。分组在未来标签可知前完成；缺失标签仅从标签诊断中排除，不从交易选择中排除。
- 顶底差大但顶部未稳定优于中间组时，优先考虑信号是否主要识别高风险或差股票。底部多头篮子的亏损不能反号视为可做空利润；借券、融资和可卖空条件需另行验证。
- 模型比较使用配对日期及冻结的时间依赖统计。历史收益或 IC 点估计更好，不等于统计上证明更优；单因子做多亏损也不等于它没有组合增量价值。

## 第三步：检查成本、换手与执行

- 明确成本是单边还是完整双边，换手计一侧还是买卖双方。分别报告零成本、基准成本与冻结的压力情景，解释逐日费用率之和与复利收益差的区别。
- 检查买不到留现金、延迟退出、锁仓资金、未确定终值，以及低流动性证券是否主导结果。未知终值的实际收益保持空值，参考估值和零回收压力分开展示。
- 缓冲区、较低调仓频率或更长持有期只做有限且事前登记的独立方案。不得把旧 T+6 退出临时顺延来美化原策略；说明改变了哪些日期、标签适配和风险承担。
- 更换交易跨度后，不将全部收益改善归因于节省成本。复用较短目标训练的预测时，明确它只是执行敏感性分析。
- 资金规模线性放大成交额、再除以 ADV 只能作为流动性压力提示；注明 ADV 时点与缺失覆盖，不称为冲击模型或可交易容量认证。

## 第四步：核查新验证资格

- 检查 manifest、试验账本和既有研究记录，确认哪些日期被看过或参与选择。日期超过旧报告截止日，不足以证明未消费。
- 有可信未消费区间时，先冻结最终模型和策略，再一次性评价。没有时如实说明；用户已授权未来观察的，可登记纸面协议，不把建立 Skill 或一般历史归因解释为新增自动跟踪授权。
- 纸面观察在真实入场前冻结当周发布、代码、参数和全截面预测；错过的周记录为 missed，不能事后补预测。规则变更创建新版本，不沿用旧 OOS 身份。
- 区分“协议已登记”“定时检查已启用”“预测已冻结”“已有成交及收益”和“观察期已完成”。只有安排了日程不能称为已经启动并完成样本外验证。
- 需要安排已授权的定时跟踪时，先查看是否已有对应自动任务，优先复用；状态不变时保持安静，只报告有意义的进展、失败或数据需求。本 Skill 不要求默认创建自动任务。

## 交付与完成判断

先给收益来源和判断边界，再给方法与程序细节。交付中文报告，包含逐因子及组合的年度表现、行业／市值／流动性贡献和覆盖、控制前后效果、分组形状、模型及成本比较、新验证实际状态。

保留能从汇总追到证券及持仓批次的明细。核验原基线、逐日和年度贡献对账、方向与模型名单、输入未变、未确定持仓情景和适用的回归测试；报告实际完成项与缺口。不能仅凭 CLI 退出成功宣布整项研究完成。

需要修复实现时，把通用逻辑留在 `src/factor_miner/` 与正式 CLI 中，同步中文合同和有意义的合成测试。Skill 只链接实现，不保存真实数据、完整历史结果、密钥或另一份回测代码。
