# 执行入口与产物核验

## 当前已实现的范围

正式入口为 `factor-miner run-eight-factor-study CONFIG_PATH`，实现位于 [eight_factor_study.py](../../../src/factor_miner/eight_factor_study.py)，使用 [causal_backtest.py](../../../src/factor_miner/causal_backtest.py) 的持仓状态机。完整的实例参数以[八因子归因合同](../../../docs/contracts/八因子归因与策略诊断.md)为准。

这条命令目前专用于已有八因子 Ridge 运行的复核，要求源运行含 `models.baseline_ridge`，并与声明的八因子名单及顺序相符。它不是任意因子数量、任意市场或任意模型的通用执行器。其他研究可沿用 Skill 的决策流程；实际计算前先核对 CLI 支持范围，需要扩展时修改核心实现与合同，不伪造输入凑成八因子。

实例中的日期、因子编号、SIC 分类、市值边界、交易周期和预算下限是该版本约定。一般流程要求继承真实研究历史并事前冻结新预算，不把 12541 当成跨任务永久常量，也不能借新任务缩减旧预算。

## 配置与输入检查

先读取源运行的 `protocol.json`、`identity.json` 和输入清单，核对实际数据身份。配置文件放在独立产物目录，真实路径不写入可提交的模板。

| 字段 | 当前执行器要求 |
| --- | --- |
| `output_root` | 全新的结果目录；已存在则失败 |
| `source_strategy_root` | 含 `protocol.json`、`weekly_panel.parquet`、`predictions.parquet`、`fit_audit.json` 及 `baseline_ridge/backtest_20bps.json` |
| `dataset_root` | 含冻结 `manifest.json`、`market.parquet`、`state.parquet`、`calendar.parquet`；标签已包含在源周面板 |
| `terminal_events_path` | 与原运行一致的可追溯终止结算表 |
| `crsp_prices_path` | `security_id`、`session_date`、`market_cap`；当前适配按 CRSP 千美元单位转换 |
| `crsp_master_path` | `security_id`、`valid_from`、`valid_to`、`sic_code`；同证券同日冲突分类失败 |
| `factors` | 恰好八项，各含 `factor_id`、`direction`、`report_path`；原报告的身份和假设方向一致 |
| `contract` | 本次适用的冻结中文研究合同 |
| `diagnostic_family_size` | 当前合同至少 `12029 + 512`；已有研究预算更大时不得缩减 |
| `hac_lags` | 当前实现固定为 `5` |
| `costs` | 使用下列固定结构；其他成本需新版本支持 |
| `input_sha256` | 上述全部实际输入文件的路径到 SHA-256 映射，不能只填清单哈希 |

```json
{
  "single_factors": [20],
  "5d_combinations": [0, 10, 20, 40],
  "10d_combinations": [20, 40],
  "bottom_long_baskets": [20]
}
```

在仓库根目录执行。下例假设事前配置已写入独立目录，不能直接沿用旧配置的输出路径。

```bash
uv run factor-miner run-eight-factor-study artifacts/my_attribution/config.json
```

CLI 会先登记，再验证输入并生成代码快照与结果。遇到身份、分类冲突或损益对账错误，先查明并修复原因；旧失败目录保留，修订协议或输入后在新目录重试。报告渲染更正使用新文件或版本回执，不能覆盖不可变统计产物。

## 产物与对应核验

| 研究问题 | 产物与核验 |
| --- | --- |
| 原策略是否复现 | `baseline_parity.json`：每日收益长度和最大差异；必要时同时查日期与选择名单 |
| 哪些年份和群体贡献收益 | 每个 `*_5d_*_20bps/` 的 `yearly.json`、`group_attribution.json`、`pnl_attribution.parquet` |
| 汇总是否真实对账 | 每个已归因篮子的 `reconciliation.json`，并核验各维度年度贡献分别加总至区间收益 |
| 数据覆盖是否足够 | `signal_characteristics.parquet`、`data_coverage.json`；缺失行业／市值年仍保留收益和未知组 |
| 控制后还剩什么 | `conditional_ic.parquet`、`score_summary.json`；控制前后是相同完整样本，覆盖期可能少于全期 |
| 因子识别强股还是差股 | `weekly_ic.parquet`、`deciles.parquet`、`stratum_ic.parquet`；同时查各组标签覆盖 |
| 模型、成本和持有期比较 | `execution_plan.json`、`strategy_summary.json` 和各方案 `backtest.json` |
| 成交与终值是否可追溯 | 归因篮子的 `orders.parquet`、`selections.parquet`、回测中的未确定持仓与参考／压力估值 |
| 输入与代码身份 | `protocol.json`、`identity.json`、`code/`、追加式 `events.jsonl`，结束后再次核对输入哈希 |

当前命令完成十个评分模型和二十二个执行场景，其中十二个五日、20 bps 篮子保存逐笔归因。该场景数用于核对当前固定实例，不能代替未来新协议自己的完成清单。

配对模型显著性、资金规模压力汇总、中文报告渲染及未来观察登记不是该 CLI 自动完成的全部能力。需要时从已保存结果继续生成可追溯的派生汇总，或在核心 CLI 增加受测入口；不要把 CLI 的 `completed` 误报为报告与纸面观察也已完成。

## 验证入口

修改计算行为时选取对应测试；只整理 Skill 文档时验证 Skill 结构、相对链接和命令存在性即可，无需重跑历史真实研究。

```bash
uv run python -m pytest -q tests/test_eight_factor_study.py tests/test_causal_backtest.py tests/test_ridge_strategy.py
uv run factor-miner run-eight-factor-study --help
```

重点不变量是历史分类不回填、不外推，未知市值独立分组，终止回收与费用进入损益对账，控制变量能移除合成的风格相关性，新持有期不修改原窗口，以及未来标签不影响更早的预测。
